# ADR-023. Protocol v9: debug-телепорт по мировой карте

**Статус:** принят
**Дата:** 2026-11-12
**Связано:** ADR-004, ADR-020, `docs/PLAN.md` §6.9

## Контекст

Для проверки урона, лута, респавна и визуала мобов в жёлтой и красной зонах приходилось
долго идти персонажем через полмира. Это замедляло и ручную проверку, и скриншот-прогоны
агента. Нужен быстрый переход в произвольную точку, в первую очередь для тестирования,
во вторую — для игрока, который хочет осмотреть карту.

Клиент уже рисует HUD на IMGUI и имеет серверный валидатор команд. Нельзя добавлять
скрытое изменение позиции на клиенте: позиция должна оставаться авторитетной на сервере.

## Решение

1. **Новая команда протокола.** `TeleportCommand` содержит `Destination: Vector2` (мировые X/Z),
   `ClientTick` и `Sequence`; кодируется тегом `9` и payload ровно 17 байт
   (`tag + tick + sequence + two singles`). `Protocol.Version` поднят с 8 до 9.
2. **Валидация.** `InputValidator.ValidateTeleport` принимает команду только при
   `ServerOptions.AllowTeleport = true`, иначе отвечает `TeleportDisabled`; точка вне
   `ZoneMap` отклоняется с `TeleportOutOfBounds`. Остальные проверки (сущность, смерть,
   rate limit) общие для всех команд.
3. **Симуляция.** `Simulation.ApplyTeleport` игнорирует мёртвую сущность, зажимает точку
   `Zones.ClampToBounds` и применяет её только если точка попадает в зону. Никаких
   коллизий и raycast: это осознанный debug-переход, а не игровое заклинание.
4. **Предсказание.** `ClientPrediction` сразу ставит X/Z из `TeleportCommand`, поэтому
   камера не ждёт снапшот. Серверный снапшот остаётся источником истины и при расхождении
   реконсиляция исправляет позицию.
5. **UI.** В правом нижнем углу HUD — миникарта всего мира в натуральном соотношении 3:1
   (`Zones` 960×320). `ALT+ЛКМ` внутри карты переводит экранную точку обратно в мировые X/Z,
   отменяет текущую pointer-метку и вызывает `ClientPipeline.SendTeleport`. Карта входит
   в hit-test HUD, поэтому ALT-клик не превращается в команду движения.
6. **Включение.** Обычные unit-тесты и in-memory сервер оставляют `AllowTeleport = false`
   и проверяют отказ. UDP-сервер из `Program` включает флаг и печатает предупреждение
   `DEBUG: телепорт включён`. Так функция не появляется в боевом режиме случайно.

## Альтернативы

| Вариант | Почему отклонён |
|---|---|
| Телепорт только на клиенте | Расхождение с сервером, читерский обход коллизий и валидации |
| Отдельный debug-HTTP endpoint | Новый канал, аутентификация и порт; команда уже есть в протоколе |
| Клик по миру без ALT | Случайные переходы во время боя и движения |
| Квадратная карта 300×300 | Искажает мир 960×320 примерно втрое; плохо читаются зоны и проходы |
| Полноценный waypoint-граф | Избыточно для debug-перехода; карта — не навигация мобов |

## Последствия

- Клиент и сервер обязаны обновиться вместе: версия протокола 9. Старые клиенты получат
  отказ на handshake, это ожидаемо.
- `AllowTeleport` — осознанная debug-настройка. Для публичного сервера её нужно держать
  выключенной; в коде UDP-точки входа она включена только на время тестового среза.
- Миникарта не влияет на симуляцию и не сериализуется; это слой представления.
- Регрессии: `CommandCodecTests`, `InputValidatorTests`, `TeleportTests`,
  `HudSmokeChecks` (геометрия 3:1, hit-test, отсутствие перекрытия с окном крафта) и
  `MobVisualSettings.ValidateMaterials` (белая эмиссия скелетов).
