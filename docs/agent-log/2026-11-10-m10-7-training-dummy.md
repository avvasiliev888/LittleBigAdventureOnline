# Agent log — 2026-11-10 — M10.7 training dummy / self-damage

## 10:00–10:35 UTC — M10.7: no self-damage, server dummy, combat verification

### Human-Gate finding

The operator reported that Space made the player hit himself: the Attack swing was immediately
interrupted by Hit and the damage arrived before the swing finished. Root cause was client-side:
`ClientRuntime.ResolveAbilityTarget` returned `_pipeline.EntityId` when no other entity existed.
The server accepted that self-target, `Simulation.ApplyAbility` reduced the caster's HP, and
`UnityView` correctly presented the HP drop as Hit — which took priority over the Attack one-shot.

### Decisions

- **No self-target at either layer.** The client returns `0` when no other living entity exists and
  does not send an `AbilityCommand`. `InputValidator` rejects self-target with a new
  `CommandRejectReason.SelfTarget`; `Simulation.ApplyAbility` also refuses `target.Id == caster.Id`
  as defense in depth. Protocol, prediction and delta contracts are unchanged.
- **Dummy is a server-owned entity, not a second control path.** `config/actors.json` gains actor 2
  (100 HP, moveSpeed 1.0, respawn 5 s, same ability definition for config completeness). The server
  entry point enables `ServerOptions.SpawnTrainingDummy`; the first player still receives entity 1,
  the dummy is entity 2 at `(4, 0, 0)` (player spawn is `(2, 0, 0)`).
- **Patrol without trusting client input.** Each server tick appends an internal `MoveCommand` for
  entity 2, reversing at `spawn.X ± 0.5`; the position is clamped to the same window after the
  simulation tick. This exercises remote interpolation and the Walk blend at 1 m/s. Dead dummy does
  not move; it respawns through the existing simulation path.
- **Rendering is generic.** `UnityView` already creates a Warrior visual for every snapshot entity;
  no dummy-specific prefab or colour branch was added. This keeps the remote Walk/Hit/Death path
  identical to a real remote player and avoids another asset dependency.
- `SpawnTrainingDummy` defaults to `false` in `ServerOptions` so existing unit/integration tests
  remain one-player by default; `Program` turns it on for both demo and UDP runs.
