# Демо-сценарий M12

Цель: за несколько минут показать, что прототип запускается, два клиента видят друг друга,
способность наносит урон, манекен умирает и респавнится, а плохая сеть не ломает управление.

## Подготовка

Из корня репозитория:

```powershell
git lfs pull
dotnet build Prototype.sln -c Release
pwsh -File tools/unity/build-plugins.ps1
```

Соберите desktop-клиент: **Unity → Albion → Build → Desktop** (или batch-команда из
`README.md`). Проверьте, что есть
`unity-client/Builds/desktop/AlbionPrototype.exe`.

## Быстрый запуск

```powershell
# один сервер + два клиента, окна останутся открытыми
pwsh -File tools/demo/start-demo.ps1
```

Лаунчер пишет лог сервера в `artifacts/demo/server.log`. Клиенты подключаются к
`127.0.0.1:9050`; если порт занят, задайте `-Port 9051`.

Эквивалент вручную:

```powershell
dotnet run --project src/Server -c Release -- --udp 9050
cmd /c start "" ".\unity-client\Builds\desktop\AlbionPrototype.exe" -serverPort 9050
cmd /c start "" ".\unity-client\Builds\desktop\AlbionPrototype.exe" -serverPort 9050
```

## 1. Два клиента и движение

1. В первом окне пройдите **WASD** вправо и влево. Камера следует за игроком.
2. Во втором окне первый игрок виден как удалённая сущность; его движение плавное, с задержкой
   отображения 2 тика (100 мс), но без телепортов.
3. В HUD обоих клиентов растут `snapshots`, `delta`; после старта `fullReq` не увеличивается на
   стабильной сети.

Ожидаемый лог сервера:

```text
[t0] server started: tickRate=20, maxCommandsPerTick=5
[t…] conn 1: Hello принят, сущность 3 ...
[t…] conn 2: Hello принят, сущность 4 ...
```

## 2. Способность, смерть и респавн манекена

1. Подойдите к тренировочному манекену (entity 2, 100 HP) на дистанцию удара (радиус 3 м).
2. Удерживайте **Space** или **ЛКМ**. Авто-атака идёт раз в 2 с; каждый удар — 25 урона.
3. HP-бар манекена: 100 → 75 → 50 → 25 → 0. На четвёртом ударе проигрывается Death, манекен
   лежит; примерно через **5 с** он респавнится в исходной точке с 100 HP.
4. Оба клиента видят HP/Death/respawn по снапшотам. После респавна манекен снова выбирается
   ближайшей живой целью.
5. Во время кулдауна HUD-иконка меча серая и заполняется; движение WASD/ПКМ при этом работает.

Ожидаемый лог сервера (пример):

```text
[t0] training dummy: entity 2, actor 2, spawn <...>
[t…] conn 1: Hello принят, сущность 3 ...
[t…] conn 2: Hello принят, сущность 4 ...
```

Сервер не логирует каждый hit/Death: смотрите HP-бар, анимацию и возврат манекена. В лог попадают
подключения, отклонённые команды и (при `--metrics-every`) метрики тика.

## 3. Два клиента и оружие

- Второй игрок виден первому; HP и мана-полоски видны над обеими сущностями.
- **1** — меч, **2** — топор: переключение мгновенное и только в своём окне; у удалённого игрока
  остаётся меч (это клиентская визуальность, протокол не меняется).
- **Ctrl** — шаг; **ПКМ** — движение к курсору; **Space + ПКМ** — бег с авто-атакой.

## 4. Плохая сеть

Клиент не переподключается к перезапущенному серверу автоматически, поэтому:

1. Закройте оба клиента и старый сервер.
2. Запустите сервер с задержкой 100 мс и потерями 30%:

   ```powershell
   dotnet run --project src/Server -c Release -- --udp 9050 --delay 100 --loss 30
   ```

3. Запустите двух клиентов заново.

Ожидаемо:

- движение остаётся отзывчивым (клиент предсказывает локально);
- при коррекциях возможны короткие плавные подтягивания, без «резинки» на каждом пакете;
- `reconciles` в HUD растёт при реальных расхождениях, `fullReq` — при потере базы дельты;
- способность и смерть/респавн продолжают работать; клиент не зависает.

Сервер печатает строку вида:

```text
сеть: задержка 100 мс (2 тик(а)), потери 30% ненадёжных пакетов
```

## 5. Автоматический smoke двух клиентов

Если не хочется вручную закрывать окна:

```powershell
pwsh -File tools/demo/start-demo.ps1 -Seconds 8
```

Скрипт запустит сервер и два клиента, через 8 секунд закроет их и проверит, что сервер принял
два `Hello`. Это проверка запуска и подключения, а не замена визуальному демо.

## Чеклист демо

- [ ] Оба клиента подключились, видят друг друга.
- [ ] WASD/ПКМ двигают локального игрока; удалённый едет плавно.
- [ ] Space/ЛКМ наносит урон; HP-бар манекена падает.
- [ ] Манекен умирает и через ~5 с респавнится.
- [ ] 1/2 переключают оружие; щит остаётся.
- [ ] При `--delay 100 --loss 30` управление отзывчивое, HUD показывает коррекции/полные снапшоты.
- [ ] Нет крашей, зависаний и magenta-материалов.

## Если что-то не так

| Симптом | Причина / действие |
|---|---|
| Второй клиент не подключается | Порт занят или сервер не запущен; `-Port`/`-serverPort` |
| Виден только один игрок | Второе окно не запущено или сервер отклонил Hello; смотрите `server.log` |
| Нет урона | Цель дальше 3 м или кулдаун; подойдите ближе и удерживайте Space/ЛКМ |
| Манекен не респавнится | Проверьте `respawnSeconds` в `config/actors.json` (5 с) |
| После плохой сети «резинка» | Уменьшите `--loss`/`--delay`; проверьте, что клиенты запущены заново |
| Magenta | `git lfs pull` и Reimport All |
