# ADR-011: Единый data-driven конфиг для сервера и Unity-клиента (M9)

- **Статус**: принято (M9)
- **Дата**: 2026-11-09
- **Контекст**: M3 завёл JSON-конфиги (`config/actors.json`, `config/abilities.json`) и загрузчик
  `ConfigLoader` на `System.Text.Json` в проекте `Server`. В M6 `ConfigLoader` переехал в `Server`,
  потому что `System.Text.Json` в `Shared.dll` не грузился в Unity (`FileNotFound`/`TypeLoad` при
  загрузке плагина). Из-за этого клиент не знал конфиг: скорость приходила в HelloAck, а радиус,
  кулдаун, `maxHp` и урон были доступны только серверу. M9 требует, чтобы клиент читал **тот же**
  JSON для предсказания и UI.

## Решение

### 1. Загрузчик переезжает в `Shared` и перестаёт зависеть от `System.Text.Json`

`ConfigLoader` (namespace `Shared`) собирается под `netstandard2.1` и `net10.0`, ссылается только
на `Simulation.Core` и BCL. `Server/ConfigLoader.cs` удалён; `Server.Program` и тесты используют
`Shared.ConfigLoader`. Один код-путь валидации для сервера, клиента и тестов — не «две копии,
которые надо синхронизировать».

### 2. Собственный минимальный JSON-парсер `MiniJson`

Вместо `System.Text.Json` — небольшой парсер в `Shared/MiniJson.cs`, который строит дерево
`Dictionary<string, object?>` / `List<object?>` / `string` / `double` / `bool` / `null`.
Поддержаны ровно те возможности, которые давал прежний загрузчик: объекты, массивы, строки
(с escape и `\uXXXX`), числа, `true/false/null`, комментарии `//` и `/* */`, висячие запятые.
Ошибки — `JsonParseException` с позицией; загрузчик заворачивает её в `ConfigValidationException`
с меткой источника (`config/actors.json: невалидный JSON …`). Глубина вложенности ограничена 64.

Парсер намеренно минимальный: это не общий JSON-движок, а часть валидации конфигов (ADR-005).
Никаких NuGet-пакетов и рефлексии, поэтому он безопасен для Unity и для netstandard2.1-плагина.

### 3. Хеш конфига как доказательство «один файл»

`ConfigLoader.ComputeHash(directory)` считает SHA-256 от содержимого `actors.json` и
`abilities.json` (в фиксированном порядке). Сервер печатает хеш при старте, клиент — в консоль
Unity и в HUD (`cfg: <8 hex>`). Тест `ClientAndServerReadSameFile_SameHash` сравнивает хеши,
посчитанные путём сервера и путём клиента; `ChangedJsonFile_ChangesHash` показывает, что правка
файла меняет хеш. Это ловит AI-Failure Mode «агент продублировал конфиг в клиенте»: копия файла
дала бы другой хеш, а её изменение не потребовало бы перекомпиляции.

### 4. Доставка файлов в Unity: `StreamingAssets/Config`

`tools/unity/build-plugins.ps1` (обязательный шаг перед открытием Unity, там же собираются
плагины) копирует `config/*.json` в `unity-client/Assets/StreamingAssets/Config/`. Каталог
генерируемый и не коммитится (`unity-client/.gitignore`), поэтому JSON в репозитории существует
ровно в одном месте. `ClientRuntime` загружает его через `ClientContent.LoadFromDirectory(
Application.streamingAssetsPath + "/Config")`; при ошибке клиент не подключается и показывает
`config error: …` с подсказкой запустить скрипт — тихого фолбэка нет (ADR-005).

### 5. Что клиент берёт из конфига

`ClientContent` (в `Client.Network`) — загруженный `SimulationConfig` + хеш. `ClientPipeline`
получает его в конструкторе и при HelloAck создаёт `ClientPrediction` по `actorId` из HelloAck:
- **предсказание движения** — `ActorConfig.MoveSpeed` вместо значения из HelloAck;
- **кулдаун способности** — `AbilityConfig.CooldownSeconds` переводится в тики (`ceil(seconds/0.05)`);
  `ClientPrediction.PredictAbility(tick, sequence)` ставит предсказанный кулдаун сразу при отправке
  `AbilityCommand`, а реконсиляция заменяет его серверным, когда sequence подтверждён (если сервер
  команду отклонил — кулдаун 0, то есть предсказание откатывается);
- **радиус** — `AbilityConfig.Range` для UI/будущего таргетинга;
- **UI** — `maxHp` актора и текущий `hp` из снапшота, кулдаун в тиках, хеш конфига.

Если `moveSpeed` в клиентском файле расходится с серверным HelloAck, клиент пишет в лог
`[config] клиент и сервер расходятся…` (видно в HUD/консоли), но продолжает работать по файлу:
поведение data-driven, а расхождение — сигнал оператору.

### 6. Ввод способности (M9, минимальный)

`UnityInputSource` по Space отправляет `AbilityCommand` по ближайшей сущности, а если других нет —
по себе (сервер это разрешает: дистанция 0 ≤ radius). Это даёт наблюдаемый кулдаун/урон в HUD и
позволяет проверить «изменил JSON → изменилось поведение» без отдельного NPC. Таргетинг мышью и
полноценный боевой UI — вне M9.

## Последствия

- Один загрузчик и один набор файлов на сервер и клиент; `System.Text.Json` больше не участвует в
  Unity-сборках, проблема M6 закрыта архитектурно, а не обходным путём.
- Минимальный парсер надо сопровождать: грамматика зафиксирована тестами `MiniJsonTests`
  (валидные документы и ошибки с позицией).
- Копирование в `StreamingAssets` — шаг сборки: забыли запустить `build-plugins.ps1` — клиент
  явно скажет об ошибке конфига, а не будет молча работать на константах.
- Хеш — диагностика, а не протокол: несовпадение не блокирует соединение (иначе пришлось бы менять
  протокол и ломать v4), но видно в логах и HUD.
