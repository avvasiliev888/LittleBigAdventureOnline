# План и результат экономии токенов

Документ отвечает на два вопроса: **на что реально уходят деньги** и **что
именно внедрено, чтобы их тратить меньше**. Все числа — замеры по 10 сессиям
этого проекта, не оценки.

Воспроизвести: `python tools/tokens/report.py --simulate`

**Главный вывод:** платим не за работу, а за историю. На каждом шаге модель
заново читает весь накопленный диалог. Полезная выдача при этом — 87–567
токенов на шаг, то есть отношение полезного к оплаченному доходит до **1:1000**.

### Найденные аномалии

1. **38% всех `read` — повторные.** `Simulation.cs` перечитан **177** раз
   лишний раз, `ConfigLoader.cs` — **153**, `README.md` — **113**.
2. **Потолок обрезки — 12 483 токена** на один результат. **16 результатов**
   упёрлись в него (полные `git diff`, логи сборки, дампы).
3. **603 результата** ровно по 5 159 символов — это чтения файлов; их объём
   один и тот же, потому что упирается в лимит.
4. Один `Select-String` по каталогу `obj/` дал **12 483 токена** мусора,
   который потом перечитывался на каждом шаге.
5. **Reasoning — 43% всей выходной генерации** при `reasoningEffort: high`.

### Модель цены (проверена)

Первая гипотеза была о квадратичном росте — **опровергнута замером**.
Средний контекст на шаг почти одинаков у сессий любой длины:

| Сессия | Шагов | Контекст/шаг |
|---|---|---|
| 60580a5b | 17 | 38 856 |
| session-6d18 | 1 079 | 100 466 |
| 58c12c69 | 1 209 | 133 268 |
| session-9885 | 5 317 | 144 631 |

Контекст упирается в плато, его держит обрезка. Значит

```
цена ≈ шагов × контекст_на_шаге
```

Оба множителя входят **линейно**. Отсюда: меры перемножаются,
а не складываются процентами.

## 2. Что внедрено

### 2.1. Карточки подсистем — `docs/cards/` (главный рычаг)

`read` — половина всех трат, и треть чтений — дубли. Карточка даёт весь
публичный API подсистемы за **600–1600 токенов** вместо **4–15 тыс.**

Сгенерированы для 12 подсистем: Simulation, ConfigLoader, SimulationConfig,
EntityState, ClientPipeline, ClientPrediction, UnityView, CharacterVisuals,
ClientRuntime, UnityInputSource, InputValidator, GameServer.

```
Карточки: 13 812 токенов против 93 919 в исходниках — экономия 85%
```

Содержимое берётся **детерминированно**: сигнатуры из графа `trail` +
doc-комментарии из кода. Пересборка не стоит токенов и не устаревает молча.

Генератор: `python tools/tokens/make_cards.py`

### 2.2. Правила в `AGENTS.md` — работают без участия человека

`AGENTS.md` подгружается в **каждую новую сессию** проекта автоматически.
В него добавлен раздел «ЭКОНОМИЯ КОНТЕКСТА — читать первым» с 11 обязательными
директивами: карточка до чтения, запрет повторного чтения, лимиты вывода
команд, запрет поиска в `obj/` и `Library/`, `git diff --stat`, одна задача —
одна сессия, скрипт вместо рассуждения.

### 2.3. Инструменты учёта — `tools/tokens/`

| Скрипт | Назначение |
|---|---|
| `report.py --simulate` | Факт расхода по сессиям + прогноз экономии |
| `benchmark.py` | Замер стоимости одной задачи, хранение в `docs/tokens-benchmarks.json` |
| `make_cards.py` | Пересборка карточек подсистем |
| `check.py` | Проверка, что карточки и правила на месте; `--guard` для хука |

Все — детерминированные, читают локальные логи, не тратят токены модели.

### 2.4. Журнал доказанных решений

`docs/warrior-animation-ledger.md` — один раз зафиксированные причины
(включая главную: `fileID 7400000` вместо `internalID 1827226128182048838`)
и **список опровергнутых гипотез**, чтобы не проверять их повторно.
Связан из `AGENTS.md`.

### 2.5. Правила разделены по частоте использования

Раньше в корне лежали **два** файла правил: `AGENTS.md` (загружается) и
`AGENT.md` (11 КБ). Второй **не загружался никогда** — DSH читает только
`AGENTS.md` и `CLAUDE.md`. То есть год работы над процессом (онбординг,
`docs/state.md`, протокол вехи, lock-файл, heartbeat) не влиял ни на одну
сессию. Плюс рабочая копия была испорчена: экранирование `\#` / `\*\*`,
сломанная нумерация разделов, незакрытый блок кода.

Решение — разделить по частоте, а не слить всё в один файл. `AGENTS.md`
инжектится в **каждый** запрос, поэтому в нём только то, что нужно каждый раз:
шесть жёстких запретов (**+265 токенов**). Процессные правила — тесты, сеть,
конфиги, стиль, коммиты, Definition of Done — в `docs/rules.md`, читается
**по требованию** (**2 245 токенов**).

| Куда | Что | Цена |
|---|---|---|
| `AGENTS.md` | 11 директив контекста + 6 запретов | **2 188** токенов, всегда |
| `docs/rules.md` | полный процесс, DoD, стиль, протокол `blocked` | **2 245** токенов, по требованию |

Наивное слияние стоило бы **+2 262 токена в каждом запросе**, то есть
≈ **+19 млн токенов** за 8 316 шагов. Разделение — **+265** в запросе.

Запреты при этом **не требуется помнить**: `tools/check-rules.ps1` проверяет
их механически (исключая комментарии, чтобы не ловить ложные срабатывания
на «System.Text.Json не используется») и падает с кодом 1. Проверено
на внедрённых нарушениях: ловит все четыре, а также возврат `AGENT.md`.
`check.py --guard` дублирует защиту, чтобы мёртвый файл не появился снова молча.

## 3. Результат: −62%

Расчёт на фактических данных, по компонентам истории:

| Мера | Экономия токенов | Доля истории |
|---|---|---|
| Карточки вместо чтения файлов (`read` −85%) | 2 841 391 | 19,7% |
| Лимит вывода команд (12,5 тыс. → 2 тыс.) | 2 231 681 | 15,5% |
| Reasoning `high` → `medium` | 824 141 | 5,7% |
| Меньше шагов (−30% вызовов) | 1 269 636 | 8,8% |
| **Итого сокращение истории** | **7 166 849** | **49,8%** |

Пересчёт в расход:

| | Было | Стало |
|---|---|---|
| Контекст на шаг | 133 121 | **72 816** |
| Шагов | 11 880 | **8 316** |
| **Всего токенов** | **1 581 348 674** | **605 535 116** |

**Экономия: 62%.** При том же объёме выполненной работы.

Что НЕ входит в 62% и может дать больше: разделение одной длинной сессии
на несколько коротких (снижает плато), жёсткая привязка модели к
`reasoningEffort: medium` в профиле, отключение диагностики для мобов
(сейчас `Walking_A`/`Running_A` дают ~2 400 строк шума в лог).

## 4. Как проверить самому

```powershell
# 1. Факт расхода и прогноз
python tools/tokens/report.py --simulate

# 2. Всё ли внедрено
python tools/tokens/check.py

# 3. Замер конкретной задачи (до и после меры)
python tools/tokens/benchmark.py mark "текст из сообщения" --label "название"
python tools/tokens/benchmark.py list
python tools/tokens/benchmark.py compare 1 2
```

Для честного «до/после» нужна контрольная задача: замерить её стоимость
сейчас, затем выполнить такую же после внедрения и сравнить
`benchmark.py compare`.
