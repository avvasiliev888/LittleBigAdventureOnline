# Unity-проект (клиент)

Здесь живёт Unity-клиент. Правила (ADR-001, ADR-006):

- авторитетной игровой логики в `MonoBehaviour` нет — только отображение и ввод;
- `Simulation.Core` подключается к клиенту **только** через `Bootstrap` и `Prediction`;
- `*.meta` трекаются git, бинарные ассеты > 100 KB — через Git LFS.

Версия редактора фиксируется в `ProjectSettings/ProjectVersion.txt` (Unity 6.3 LTS, 6000.3.x).

## Как запустить (M6)

1. Собрать плагины (netstandard2.1 → `Assets/Plugins/Albion`, каталог не коммитится):

   ```
   pwsh -File tools/unity/build-plugins.ps1
   ```

2. Запустить сервер в отдельном терминале из корня репозитория:

   ```
   dotnet run --project src/Server -c Release -- --udp 9050
   ```

3. Открыть `unity-client` в Unity 6.3, открыть сцену `Assets/Scenes/Arena.unity` (M10), нажать **Play**.

Клиент запускается сам (`ClientRuntime` через `RuntimeInitializeOnLoadMethod`): подхватывает сцену
арены (пол, колонны, камни, кристаллы, свет, Volume) или, если сцены нет, создаёт окружение сам;
подключается к серверу, шлёт `MoveCommand` по WASD и двигает стилизованных персонажей
по интерполированным снапшотам (лаг отображения 2 тика = 100 мс).

Настройки подключения:

- переменные окружения `ALBION_SERVER_HOST`, `ALBION_SERVER_PORT`;
- аргументы командной строки `-serverHost 127.0.0.1 -serverPort 9050` (для билда).

## Предсказание и плохая сеть (M7)

Клиент предсказывает движение игрока по `moveSpeed` из HelloAck и реконсилирует его по `ServerAck`
(ADR-009). В HUD вторая строка:

```
prediction: reconciles=0 | lastError=0.000 | pos=(3.42, 0.18) | unacked=0
```

- `reconciles` — сколько раз реально сработала реконсиляция (на стабильной сети остаётся 0);
- `unacked` — сколько команд ещё не подтверждено сервером;
- каждая реконсиляция пишется в консоль Unity: `ClientRuntime: реконсиляция tick=… error=…`.

Имитация плохой сети включается флагами сервера (задержка в обе стороны + потери снапшотов):

```
dotnet run --project src/Server -c Release -- --udp 9050 --delay 100 --loss 20
```

Ожидаемое поведение: движение отзывчивое (предсказание), редкие плавные подтягивания при коррекциях,
`reconciles` растёт только при реальных расхождениях.

Как рисуются игроки (M7):

- **локальный игрок** — без задержки буфера: позиция сразу следует за предсказанием, между тиками
  20 Гц экстраполируется по времени (dead reckoning) по скорости из отправленной команды, коррекции
  реконсиляции гасятся визуальным оффсетом (~120 мс), поэтому управление ощущается мгновенным,
  без телепортов; сэмплы подаются каждый клиентский тик, джиттер сети на тайминг не влияет;
- **удалённые игроки** — через буфер снапшотов с задержкой 2 тика (100 мс) и интерполяцией, чтобы
  ехали плавно даже при потерях и джиттере.

## Дельта-снапшоты и пропуски (M8)

С M8 сервер не дублирует неизменённые поля: после первого полного снапшота каждый тик приходит
`Delta` (ненадёжно) с базовым тиком, а полный `Snapshot` — только когда базы у клиента быть не может
(первое подключение, ответ на `FullSnapshotRequest`, разрыв). Формат и обоснование — ADR-010,
протокол v4.

В HUD первая строка показывает:

```
Albion: connected | snapshots: 412 (delta 409, fullReq 2) | WASD — движение
```

- `delta` — сколько дельт успешно применено; на стабильной сети растёт каждый тик;
- `fullReq` — сколько раз клиент потерял базу (потеря пакета) и запросил полный снапшот. При `--loss 20`
  это единицы-десятки за минуту, при стабильной сети — 0 после первых снапшотов;
- если дельта не применяется (нет базы), клиент не «залипает»: запрос полного идёт по надёжному
  каналу с кулдауном 0.3 с, восстановление занимает 1–2 тика.

Проверить объём вживую:

```
dotnet run --project src/Server -c Release -- --udp 9050
dotnet run --project tools/test-client -c Release -- 127.0.0.1 9050 10
```

в итоговой строке — `снапшотов=N (дельтами M)` и `запросов полного снапшота=0`.

Клиент хранит историю 16 последних снапшотов (0.8 с); при задержке больше этого окна дельты будут
терять базу и клиент перейдёт на полные снапшоты — корректно, но дороже по трафику.

## Data-driven контент (M9)

Клиент читает тот же JSON, что и сервер, тем же загрузчиком из `Shared` (ADR-011):

- `tools/unity/build-plugins.ps1` копирует `config/actors.json` и `config/abilities.json` в
  `Assets/StreamingAssets/Config/` (каталог генерируемый, в git не попадает);
- `ClientRuntime` грузит его при старте; при ошибке в HUD видно `config error: …` и клиент не
  подключается (тихого фолбэка на константы нет);
- в HUD появились `cfg: <первые 8 символов SHA-256>`, `hp: X/Y`, `cd: N тиков`, `range: R`, а
  хеш должен совпадать с серверным (`config: … hash: …` в логе сервера).

Что берётся из конфига:

- скорость предсказания — `actors[].moveSpeed`;
- радиус и кулдаун — `abilities[].range` / `cooldownSeconds` (в тиках `ceil(sec/0.05)`);
- `maxHp` актора для HUD; текущий HP — из снапшота.

Space отправляет `AbilityCommand` по ближайшей сущности (если других нет — по себе): в HUD сразу
виден кулдаун в относительных тиках (`cd: 40` → 0), сервер подтверждает его в снапшоте. Нажатие
запоминается каждый кадр (`PollFrame`), поэтому не теряется между тиками и работает стоя на месте.
Пока кулдаун идёт, нажатие игнорируется локально: команда не уходит на сервер, урон не меняется.
HP предсказывается только сервером — локального урона в клиенте нет. Проверка data-driven:

1. измените `config/abilities.json` (`cooldownSeconds` 2 → 6, `damage` 25 → 5) и `config/actors.json`
   (`moveSpeed` 4 → 6);
2. перезапустите сервер, снова запустите `pwsh -File tools/unity/build-plugins.ps1`;
3. перезапустите Play (код не перекомпилируется): движение быстрее, кулдаун ~120 тиков, урон 5,
   `cfg:` хеш другой.

## URP, стилизация и два профиля качества (M10)

Рендер-пайплайн — URP 17.3.0 (пакет поставляется с Unity, установка не требует сети, ADR-012).
Ассеты и сцена генерируются редакторскими скриптами и лежат в git:

- `Albion/Rendering/Setup URP` (`Assets/Editor/AlbionUrpSetup.cs`) — два renderer data и два
  `UniversalRenderPipelineAsset`: `Assets/Resources/Rendering/UrpDesktop.asset` (deferred, HDR,
  MSAA 4x, тени 2048/60, GPU Resident Drawer, Bloom+Vignette+ColorAdjustments) и `UrpMobile.asset`
  (forward, без HDR/MSAA/пост-обработки, render scale 0.8, тени выключены);
- `Albion/Rendering/Validate URP` — проверяет, что профили различаются и всё грузится в рантайме;
- `Albion/World/Rebuild Arena` (`Assets/Editor/AlbionWorldBuilder.cs`) — сцена `Arena.unity`
  с LODGroup (8 колонн, 6 камней), static-флагами и occlusion culling;
- `Albion/Build/Desktop|Mobile` (`Assets/Editor/AlbionBuild.cs`) — две сборки в `Builds/desktop`
  и `Builds/mobile`; mobile получает символ `ALBION_MOBILE_DEFAULT`.

Профиль выбирается в рантайме (`Assets/Scripts/Rendering/QualityProfile.cs`): `ALBION_QUALITY`,
аргумент `-quality desktop|mobile` или дефолт сборки. В HUD видно `profile: desktop|mobile` и
сглаженный `fps`; раз в 10 секунд FPS пишется в лог (`[fps] profile=… avg=…`).

Стилизация: `Assets/Shaders/ToonLit.shader` (двухцветная рампа, мягкая тень, rim, контур
inverted hull; проход `UniversalForwardOnly` работает и в deferred) и `ToonGround.shader`
(шахматка без текстур). Персонажи собраны из простых форм с палитрой герой/чужие/мёртвые:
внешние Synty POLYGON агенту недоступны (нет сети и лицензии), поэтому стилизация процедурная;
модели можно заменить, не трогая код. Occlusion-данные запекаются в batchmode; если их нет,
повторите `Window/Rendering/Occlusion Culling → Bake` в редакторе.

## Ограничения M6–M10

- Рендер-пайплайн — URP; внешние ассеты персонажей не подключены (стилизация процедурная,
  замена — на усмотрение оператора).
- Тестов Unity Test Framework в проекте нет (пакет не установлен); smoke-тесты клиента — xUnit
  `ClientPipelineTests` в `src/Tests` (подключение → ввод → снапшоты → отрисовка, предсказание
  и сходимость при задержке/потерях).
- Предсказывается движение и кулдаун способности (кулдаун из конфига); урон, ресурсы и HP — серверные.
- Таргетинга мышью нет: Space целится в ближайшую сущность, иначе в себя (M9-минимум).
- Mobile-профиль без теней (ради FPS ≥ 30); если нужны — включим в `UrpMobile.asset` и замерим.
- GPU Resident Drawer включается только на D3D12-железе; иначе URP предупреждает и продолжает работу.
