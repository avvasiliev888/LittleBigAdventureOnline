# Протокол «Тандем»

Платная модель думает и проверяет, локальная gemma пишет код, гейты решают,
человек принимает. Ничего не мержится без письменного «принято».

## 1. Роли и модели

| Роль | Модель | Провайдер | Что делает | Пишет код |
|---|---|---|---|---|
| **Архитектор** | `deepseek-v4-flash` | `openai` (LiteLLM) | интервью, план задач, ADR, чек-лист playtest | нет |
| **Исполнитель** | `ois-gemma-4-26B` | `openai` (LiteLLM) | правки строго по задаче, быстрые гейты | да |
| **Ревьюер** | `deepseek-v4-flash` | `openai` (LiteLLM) | проверка diff, вердикт JSON | нет |
| **Отладчик** | `deepseek-v4-flash` | `openai` (LiteLLM) | диагноз после 4 неудач, план починки | ≤15 строк |
| **Гейты** | `tools/tandem/gates.ps1` | — | build, test, architecture, Unity compile | нет |

Промпты ролей — `tools/tandem/prompts/<роль>.md`. Тело цикла — `tools/tandem/orchestrator.workflow.js`.

## 2. Цикл одной задачи

```
1. Взять первую задачу с "[ ]" из docs/plan_for_gemma.md
2. git checkout -b agent/T-<slug> от main
3. Исполнитель (gemma) → правки по задаче
4. Гейты: dotnet build → dotnet test → arch-скрипты → Unity compile
   провал → повтор (максимум 3 попытки исполнителя), затем эскалация
5. Ревьюер (deepseek) по diff + хвосту логов → JSON-вердикт
   PASS  → отчёт, чекбокс, стоп до «принято»
   FAIL  → must_fix в задачу, повтор с 3 (до 4 попыток)
6. После 4-й неудачи — отладчик (deepseek): диагноз + план → одна попытка gemma
7. Всё равно FAIL → стоп конвейера, отчёт «блокер», пинг (если .agent/away)
```

После всех задач фичи: `tools/unity/build-windows.ps1` → проверить `.exe` →
архитектор пишет `docs/reports/<фича>.md` → чекбоксы, `spend.jsonl`, пинг.

## 3. Триггерные фразы

| Фраза пользователя | Действие агента |
|---|---|
| «Я уезжаю» | создать `.agent/away`, подтвердить, что отчёты пойдут в файл и Telegram |
| «Я вернулся» | удалить `.agent/away`, прислать сводку: что сделано, что ждёт «принято», сколько потрачено |
| «Новая фича: …» | интервью по `architect.md` → задачи в `docs/plan_for_gemma.md` → ADR при архитектурном решении |
| «Запусти конвейер» | прочитать `tools/tandem/orchestrator.workflow.js`, выполнить его телом `workflow` |
| «Принято» / «Принято: T-012» | слить ветку `agent/T-012` в `main`, закрыть чекбокс, короткий отчёт |
| «Замечания: …» | превратить каждое замечание в задачу плана, не спорить |

## 4. Эскалация

1. **Попытки 1–2** — та же задача, тот же исполнитель, в промпт добавляется
   «смени подход: предложи 2 альтернативы, выбери лучшую, объясни почему».
2. **Попытка 3** — задача уходит отладчику: полный набор логов и релевантный код.
3. **Попытка 4** — последняя у gemma по плану отладчика.
4. **Провал** — конвейер встаёт. Не «пробовать ещё», не расширять лимиты,
   не менять задачу молча. Отчёт-блокер + пинг пользователю.

## 5. Бюджет

Перед **каждым** платным вызовом агент читает `.agent/spend.jsonl` и `config.json`:

- сумма `usd` за текущий месяц ≥ `monthly_cap_usd` (8) → стоп;
- число строк за месяц ≥ `monthly_cap_calls` (60) → стоп;
- стоп = отчёт «бюджет исчерпан» + пинг (если `.agent/away`) + ожидание человека.

Локальная gemma в лимит вызовов не входит, но её токены считаются в `usd` для
прозрачности: цена в `config.json` может быть нулевой.

## 6. Запреты

- Не мержить в `main` без письменного «принято».
- Не пушить в `main` из конвейера вообще: только ветки `agent/*` и `setup/*`.
- Не трогать файлы вне задачи (правило diff-scope проверяет ревьюер).
- Не выходить за `monthly_cap_*`.
- Не печатать `telegram.json` в логи и в чат.
- Не отключать падающий тест: чинить причину или `blocked` (`docs/rules.md` § 9).
