# Маг красной зоны: дальний бой и ледяной удар

> **Внимание:** визуальная часть (§4, «Снаряд: ледяная глыба») **переделана
> в заходе 111** — заказчик забраковал её как «белые полосочки и кружки».
> Актуальное описание эффекта, шейдера и раскадровки: `docs/mob-ice-magic.md`.
> Разделы §1–3 и §5–6 (дёрганье, дальний бой, конфиг, проверки) верны.

Заход 110, 21.11.2026. Жалоба заказчика: «маг дёргается при ходьбе» и «подходит в упор,
быстро дёргает руками». Оба симптома — не про анимацию, а про **числа и граф переходов**.

## 1. Дёрганье при ходьбе — порог на скорости моба

В контроллере `WizardBodyController` переходы шаг↔бег стояли на пороге **3,2**:

```
walk → run   Speed > 3,2
run → walk   Speed < 3,2
```

А `moveSpeed` мага в `config/mobs.json` — ровно **3,2**. Скорость в клиенте считается как
«пройденный путь / время кадра», то есть колеблется вокруг любого фиксированного порога.
Оба перехода срабатывали по очереди, и каждый вызывал `animator.Play(hash, 0, 0f)` —
клип **перезапускался с нуля**. Глазами это «шаг начинается заново, не закончившись».

Исправлено в `MobBodyImport.BuildController`:

| переход | было | стало |
|---|---|---|
| walk → run | `> 3,2` | `> 3,6` |
| run → walk | `< 3,2` | `< 3,2` |

Зазор **0,4 м/с** — это и есть гистерезис. Порог `3,6` выбран с запасом над `moveSpeed 3,0`
(скорость мага снижена с 3,2 до 3,0, см. § 2).

Вторая причина того же симптома: переходы строились через `AddAnyStateTransition`, то есть
из **любого** состояния. `Speed` пишется каждый кадр, поэтому `AnyState`-переход выбивал
моба и из атаки, и из реакции на удар — жест обрывался на первом кадре. Заменено на
`source.AddTransition(target)` — только из конкретного состояния.

## 2. Дальний бой — числа из `config/mobs.json`

Было (чистый ближний бой): `attackRange 2.4`, `attackSeconds 1.6`, `weaponType sword_2h`.

Стало:

| поле | значение | почему |
|---|---|---|
| `weaponType` | `staff` | по нему клиент выбирает ледяной снаряд |
| `attackRange` | **10.0** | «атаковал с большого расстояния, например, 10 метров» |
| `keepDistance` | **4.0** | отступает, когда игрок подошёл ближе 4 м |
| `attackSeconds` | **3.0** | один жест и пауза, а не очередь быстрых |
| `damage` | **22** | см. ниже |
| `moveSpeed` | 3.0 | 3,2 совпадало с порогом walk↔run |

**Урон поднят с 11 до 22** — это не произвол, а требование существующего теста
`RepoConfig_Mobs_HaveReadableDifficultyCurve`. Он проверяет, что DPS красного моба убивает
игрока с 130 HP за **15–22 с**. При кулдауне 3 с и уроне 11 выходило 35,5 с — маг стал бы
безопаснее синего моба. При уроне 22: `130 / (22/3) = 17,7 с` — внутри диапазона.

### Новые поля в Simulation.Core

`MobDefinition`: `KeepDistance`, `WeaponType`, вычисляемый `IsRanged`.
`MobAiState`: добавлено значение `Retreat`.
`ConfigLoader`: `keepDistance` и `weaponType` читаются через `OptionalFloat`/`OptionalString`,
поэтому старые конфиги без этих полей грузятся как раньше (`keepDistance 0` = ближний бой).

`MobDefinition` падает с `ArgumentOutOfRangeException`, если `keepDistance > attackRange`:
иначе моб отходил бы дальше, чем достаёт его удар, и бой не начинался бы никогда.

### ИИ (`Simulation.UpdateMob`)

```
если keepDistance > 0 и дистанция < keepDistance:
    AiState = Retreat
    MoveMobAway(...)          // пятится, обходя камни тем же steering
    TryMobAttack(...)         // и продолжает бить по кулдауну
```

Удар вынесен в `TryMobAttack` — отступление **не** превращается в паузу. Иначе игрок,
подошедший впор, безнаказанно убивал бы мага.
`MoveMobAway` — зеркало `MoveMobTowards`: тот же `MobSteering.Resolve` и
`MovementCollision.Resolve`, поэтому моб не проходит сквозь камни и не застревает в стене.

## 3. Жест и кулдаун

`attack` в наборе `magic` переведён с `Attack01` на **`Attack04`**:

| клип | длина | зациклен | пригодность |
|---|---|---|---|
| Attack01 | 1,0 с | **да** | сам повторялся — «много быстрых жестов» |
| Attack04 | 1,33 с | **нет** | один цельный жест, ровно как просил заказчик |

Импорт (`Albion/Mobs/Import Bodies From Sets`) перегенерировал префаб и контроллер:
`attackState: Attack04`, в контроллере состояние `Attack04`, `states=6`, `ValidateMaterials: OK`.

## 4. Снаряд: ледяная глыба

`ProjectileVfx.IceShard` — гранёная глыба: ядро-цилиндр, носок-конус вперёд по +Z,
хвост-конус назад, три ребра по кругу, точечный свет и морозный шлейф.
Скорость **24 м/с** (шар 18, стрела 34): на 10 м полёт **0,42 с** — успеваешь увидеть бросок.
Летит по прямой (дуга отключена: тяжёлая глыба не планирует) и медленно вращается вокруг
оси полёта, чтобы блестели грани.

`FrostVfx` — два новых эффекта, оба процедурные (VFX-ассетов в проекте нет):

- `ChargeAt(hand)` — морозный ореол и свет у ладони перед вылетом, 0,42 с;
- `Burst(point)` — вспышка попадания: расходящееся кольцо по земле, 26 осколков-конусов,
  холодный свет. Кольцо читается с любой камеры, чего обычные искры не дают.

Задержка снаряда **0,25 с** от начала жеста: глыба вылетает в момент броска, а не на замахе.

## 5. Адресность удара

`UnityView.PlayMobAttackNear` проигрывал жест **всем мобам в радиусе 3,5 м** от игрока —
единственный признак «кто ударил», потому что в снапшоте нет id атакующего. С дальним боем
это дало бы «руки дёргаются у всех, кроме стрелка».

Теперь радиус берётся из конфига моба (`AttackRange + 0,5`), а моб с `IsRanged` и дистанцией
больше 2,5 м дополнительно выпускает `IceShard` и `ChargeAt`. `EntityVisual` получил поле
`MobDefinition`, заполняемое при создании визуала.

## 7. Ловушки этого захода

1. **Тест поймал дисбаланс, которого не было в задании.** Кулдаун 3 с при уроне 11 делал
   мага безопаснее синего моба. Без прогона тестов это ушло бы в игру.
2. **`Config` в тестах валидирует `leashRange >= aggroRange`.** Тест с `aggroRange 14` при
   `leashRange` по умолчанию 12 падает в конструкторе, а не в проверке.
3. **Unity использует DLL из `Assets/Plugins/Albion`, а не исходники `src/`.** После правки
   `Simulation.Core` обязателен `tools/unity/build-plugins.ps1`, иначе Probe покажет
   `CS1061: does not contain a definition for 'IsRanged'`.
4. **Копию проекта для Unity делать на `F:`**, не в `%TEMP%`.
