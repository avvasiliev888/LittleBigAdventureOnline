# План: поворот к цели и подход перед ударом

**Статус:** согласован 19.11.2026, к исполнению не начат.
**Сессия:** одна задача — одна сессия (`AGENTS.md` § 9). Продолжать по чек-листу § 6.

---

## 1. Жалобы заказчика (дословно)

1. При ударе персонаж **не всегда поворачивается к цели**, которой наносит урон.
   Надо: цель в радиусе меча → повернуться, потом ударить. Цель дальше радиуса →
   сначала добежать, потом ударить.
2. При выстреле персонаж **не всегда поворачивается нужной стороной**. Стрела
   вылетает то из спины, то с противоположной стороны от лука, то из груди —
   хотя лук и голова смотрят в сторону **левого плеча**.
3. При беге с луком **голова должна смотреть вперёд**, поворачиваться влево
   только во время выстрела.

Снято заказчиком (не делать): смерть и лежание трупа — работает; стрельба на бегу —
не нужна, текущее поведение «остановился, выстрелил, побежал» верное.

---

## 2. Решения, принятые заказчиком

| Вопрос | Решение |
|---|---|
| Как включать подход к цели | **Одно нажатие = добижать, повернуться, ударить.** Один удар на одно нажатие |
| Скорость поворота | **Плавно, ~0,15–0,25 с**, удар начинается после завершения доворота |
| Ориентация при выстреле | **Левым плечом к цели**; угол — калибруемое число в настройках, как `BowHeadTurn` |
| Голова с луком в руках | **`BowAim` — влево, бег/ходьба — вперёд** |
| Источник радиусов | **`config/abilities.json`**, те же числа, что видит сервер |

---

## 3. Измеренные причины (проверено по коду 19.11.2026)

Числа и строки — факты, не гипотезы. Правку начинать с них.

### 3.1. Поворот перезаписывается движением — главная причина «не всегда поворачивается»

`unity-client/Assets/Scripts/View/CharacterVisuals.cs:272` — в `SetMotion`
каждый кадр, пока есть скорость, модель поворачивается **по вектору скорости**:

```csharp
if (!dead && speed > 0f && facing != null)
    facing.rotation = Quaternion.Slerp(facing.rotation,
        Quaternion.LookRotation(velocity / speed, Vector3.up), 1f - Mathf.Exp(-18f * deltaTime));
```

`Face()` (`:373`) ставит поворот **мгновенно**, но следующий кадр `SetMotion`
его затирает. Пока персонаж бежит — поворот к цели живёт один кадр.
Отсюда «не всегда».

### 3.2. Автоподхода нет вообще

`unity-client/Assets/Scripts/Input/UnityInputSource.cs:199` — способность уходит,
если пройден кулдаун и не играет атака; **расстояние до цели не проверяется**.
`UnityView.TriggerAttack` (`:435`) сразу играет клип и выпускает снаряд.

Сервер тоже не проверяет дальность: `src/Server/InputValidator.cs:258`
(«a missing, dead or out-of-range target is a legal miss») — кулдаун спишется,
урона не будет. Так что клиентский автоподход не «читит», а доводит до
состояния, в котором сервер и без нас нанёс бы урон.

### 3.3. Стрела вылетает из-за корпуса — причина «из спины / из груди»

`unity-client/Assets/Scripts/View/UnityView.cs:515` `AttackOrigin`:

```csharp
return weapon.position + (weapon.forward * 0.15f) + (Vector3.up * 0.1f);
```

Лук висит в **левой** руке (`CharacterVisuals.cs:597` — для `WeaponKind.Bow`
берётся `leftHandSocket`) и смотрит влево от корпуса. Корпус, повёрнутый грудью
к цели, оставляет лук под ~90° в сторону. Направление снаряда задаётся
`origin → target` (`ProjectileVfx.Arrow(origin, targetPosition, 0.08f)`),
поэтому луч идёт **поперёк тела**. Стрела вылетает сбоку и визуально
«из спины» либо «из груди» в зависимости от того, куда успел довернуться корпус.

### 3.4. Голова повёрнута всегда, пока лук в руках

`unity-client/Assets/Scripts/View/CharacterAimPose.cs:103` — коррекция работает,
если экипирован лук, **без учёта состояния**:

```csharp
if (!IsBowEquipped()) { _handWritten = false; _headWritten = false; return; }
```

Угол — константа `BowHeadTurn = -82.16f`
(`CharacterVisualSettings.cs:22`), применяется и в беге, и в `BowAim`.
Это ровно то, что заказчик видит как «голова повёрнута, когда не надо».

### 3.5. Радиусы уже есть в конфиге

`config/abilities.json`: меч (`id 1`) — **range 3.0**, лук (`id 3`) — **range 8.0**.
Активная способность актора приходит из `ActorConfig.AbilityId`;
на клиенте доступна через `ClientPrediction.AbilityRange`
(`src/Client.Network/ClientPrediction.cs:164`).

## 4. Целевое поведение

**Удар мечом.** Нажатие → клиент берёт ближайшую живую цель из снапшота →
если расстояние ≤ радиуса способности: плавный доворот за ~0,2 с → клип удара →
вспышка у клинка. Если дальше: персонаж бежит к цели (обычные `MoveCommand`,
те же, что от мыши) → при входе в радиус останавливается, доворачивается, бьёт.
Одно нажатие — не более одного удара.

**Выстрел.** То же сближение до радиуса лука. Перед выстрелом корпус
доворачивается так, чтобы левое плечо смотрело на цель (угол
`BowFacingOffsetDeg`). Точка вылета — **наконечник лука**, не «центр лука + 15 см».
Направление — на цель.

**Голова.** `BowAim` и момент выстрела — поворот влево на `BowHeadTurn`.
`Idle`/`Locomotion`/`BowIdle` при луке в руках — голова **вперёд** (коррекция головы выключена).

**Регрессии, которые ломать нельзя:**
- стрельба на бегу не включается — один слой анимации, клип выстрела останавливает ноги;
- смерть и лежание трупа не трогаем;
- поворот «по вектору движения» остаётся, когда цели нет;
- серверная логика урона не меняется (никаких правок `src/Server`).

## 5. Что менять

### 5.1. `CharacterVisuals` — доворот вместо мгновенного поворота

Новый публичный API (старый `Face` оставить, он нужен мгновенным вызовам):

- `TurnTo(Vector3 direction, float degreesPerSecond)` — включить доворот;
- `float YawOffsetDeg` — постоянный сдвиг корпуса относительно направления
  (для «левым плечом»); применяется при всех поворотах через якорь;
- в `SetMotion` — **пока доворот активен**, не поворачивать по скорости;
  гасить доворот, когда угол < 1°, или по таймауту.

### 5.2. `UnityView` — сближение и порядок «повернуться → ударить»

- `TriggerAttack` больше не бьёт сразу; он создаёт задачу атаки
  (цель + вид оружия) в очередь.
- Новый шаг в `Update`: задача активна → измерить расстояние → далеко: выдать
  точку подхода в существующий канал движения; близко: `TurnTo` → по завершении
  поворота `PlayAttack` + `SpawnProjectile`.
- Точку вылета и направление считать от наконечника лука (новый метод в
  `CharacterVisuals`: `Transform ArrowTip`), направление — на цель, **не** `weapon.forward`.

### 5.3. `CharacterAimPose` — голова по состоянию

- Условие головы — `BowAim` или активный выстрел, а не «лук экипирован».
  Состояние брать из `CharacterVisuals.LastRequestedState`.
- Расчёт угла — плавный переход к `headTurn` за ~0,15 с и обратно к нулю,
  а не скачок (сейчас скачок на -82° в первом же кадре бега с луком).

### 5.4. Настройки — калибруемые числа

`CharacterVisualSettings`: добавить `BowFacingOffsetDeg` (стартовое значение **90**),
`TurnSeconds` (стартовое **0.2**), `ApproachSlack` (запас до границы радиуса,
стартовое **0.6**). Все — с `Tooltip` и стартовыми значениями в коде,
чтобы сборка не зависела от ручной правки ассета.

## 7. Ловушки, уже стоившие времени

1. **`Fix` рапортует об успехе, ничего не записав.** После любой правки ассета —
   перечитать его или `Probe`. Смотреть `mtime`, не строку в логе.
2. **Копия проекта на `F:`, не в `%TEMP%`.** На `C:` ~18 ГБ; неполная копия
   уже дважды дала ложные прогоны.
3. **`Probe` пишет через `Debug.Log`** — текст строкой выше трассировки; искать
   `PROBE START`/`PROBE END`.
4. **Один слой анимации** (`mask=none`). Верхний слой для стрельбы на бегу
   сознательно **не делаем** — заказчик отказался.
5. **Поворот по скорости в `SetMotion`** перезапишет любую коррекцию из `Update`.
   Любой доворот делать внутри `SetMotion` или после него.
6. **Не запускать игру/сборку без прямой просьбы.**

## 8. Открытые риски

- **Наконечник лука.** Если у префаба нет отдельного объекта наконечника,
  придётся считать точку по габаритам меша. Допустимая деградация — центр лука,
  но тогда сценарий «из спины» может остаться частично. Решение — по замеру на шаге 4.
- **Задержка ввода.** Автоподход отнимает управление до удара. При промахе
  по мёртвой цели персонаж всё равно подбежит — проверить в сценарии 13.
- **Сервер и клиент разойдутся по дальности**, если `abilities.json` на клиенте
  и сервере разный. Резерв из шага 5 логировать.
