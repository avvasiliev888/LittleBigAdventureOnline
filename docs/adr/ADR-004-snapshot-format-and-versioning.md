# ADR-004. Формат снапшотов и дельт, версионирование протокола

**Статус:** предложен (ожидает Human-Gate M0)
**Дата:** 2026-11-08
**Связано:** `docs/prototype-plan.md` (M2, M4, M5, M8, M9), ADR-002, ADR-003

## Контекст

Состояние мира передаётся клиенту снапшотами: сначала полными (M2, M4), затем дельтами (M8) и с восстановлением после потери базового снапшота. Ограничения:

- клиент и сервер — разные рантаймы (Unity/C# и .NET 10), общий код — только `Shared`;
- сущностей мало (единицы–десятки), но снапшоты идут 20 раз в секунду, поэтому важен размер и отсутствие мусора;
- формат должен быть однозначным (одинаковый `float` на обеих сторонах), проверяемым тестами roundtrip и версионируемым: старая и новая версии не должны «тихо» разъехаться;
- дельта обязана восстанавливаться: потерян базовый снапшот → запрос полного, а не «залипание».

## Решение

### Бинарный формат, little-endian, ручная запись

Общий код — `Shared.Protocol` поверх `System.Buffers.Binary.BinaryPrimitives` / `BinaryWriter`-совместимой записи в `Span<byte>`. Никакой рефлексии и сериализаторов «по типу» в горячем пути.

**Заголовок сообщения (любое сообщение):**

| Поле | Тип | Примечание |
|---|---|---|
| `magic` | `uint16` | `0xA1B0` — защита от мусора/не того порта |
| `protocolVersion` | `uint16` | константа `Protocol.Version`, поднимается при несовместимом изменении |
| `messageType` | `byte` | `Hello/HelloAck/Command/Snapshot/Delta/FullSnapshotRequest/...` |
| `payloadLength` | `uint16` | длина тела, для валидации |

**Полный снапшот (`Snapshot`):**

| Поле | Тип |
|---|---|
| `tick` | `uint32` |
| `entityCount` | `uint16` |
| далее `entityCount` раз: `id uint32`, `x,y,z float32`, `hp int32`, `flags byte` (bit0 — `isDead`) | |

**Дельта (`Delta`, M8):**

| Поле | Тип |
|---|---|
| `baseTick` | `uint32` — тик, к которому применяется |
| `tick` | `uint32` — результирующий тик |
| `removedCount` + `removedId[]` | `uint16`, `uint32[]` |
| `changedCount` + записи сущностей (полная запись, без побитовых масок) | `uint16`, ... |

Изменённая сущность передаётся целиком: при десятках сущностей и 20 Гц выигрыш от частичных полей не оправдывает сложность и риск рассинхрона. Дельта «на всякий случай полная» запрещена — тест M8 сравнивает размер трафика.

### Версионирование

- `Protocol.Version` — `ushort`, живёт в `Shared`, инкрементируется при любом несовместимом изменении формата/семантики.
- Версия передаётся в handshake: несовпадение → сервер отклоняет соединение с причиной (`Reason.VersionMismatch`), клиент показывает текст, а не «висит».
- Обратная совместимость не поддерживается на горизонте прототипа (одна версия = одна сборка), но версия обязательна: она делает рассинхрон **явным** и ловится тестом M5.
- Снапшот содержит `tick`, дельта — `baseTick`+`tick`; применение дельты к неверному базовому тику — ошибка, а не «примерное совпадение».

### Потеря и восстановление

- Клиент применяет дельту только если у него есть состояние ровно на `baseTick`; иначе шлёт `FullSnapshotRequest` и продолжает интерполировать по последнему валидному снапшоту.
- Сервер хранит последние `K = 20` полных снапшотов (1 секунда) для ответа на запрос; при `K`-промахе — отвечает ближайшим полным.

## Альтернативы

| Вариант | Почему отклонён |
|---|---|
| JSON-снапшоты | Размер и аллокации при 20 Гц; нестабильное представление чисел; парсинг в горячем пути |
| MessagePack / protobuf / MemoryPack | Лишняя зависимость и генерация кода при 3–6 сообщениях; сложнее отлаживать побайтово; выигрыш незначим для наших размеров |
| Дельта по битовым маскам полей | Экономит единицы байт, но резко усложняет и делает рассинхрон «тихим» |
| Текстовый протокол поверх WebSocket | TCP-эффекты (ADR-002) и оверхед; не для 20 Гц |
| Версионирование «по хешу сборки» без номера | Не объясняет причину отказа пользователю и не даёт осмысленного текста ошибки |

## Последствия

- Нужны roundtrip-тесты (`Serialize → Deserialize → равенство по полям`) для снапшота и дельты, включая границы: 0 сущностей, максимальный `uint`, `float` без NaN/Inf (валидируется при записи).
- Формат замораживается после M1 как часть контрактов: изменения — только с подъёмом `Protocol.Version` и записью в ADR.
- Дельта требует от сервера хранить «предыдущее состояние на тик» — это память под `K` снапшотов, что при десятках сущностей ничтожно.
- `ISnapshotSerializer` замораживается в M1; реализация `SerializeDelta/ApplyDelta` (M8) добавляется как расширение, а не замена базового интерфейса без ADR.
- NaNs/Infinities запрещены в позициях: проверка на запись, тест на отказ.
