# Правила проекта LittleBigAdventureOnline

Читается **по требованию** — когда задача касается тестов, конфигов, сети,
коммитов или ассетов. В `AGENTS.md` (загружается всегда) вынесены только
жёсткие запреты и дисциплина контекста; всё остальное — здесь, потому что
оплачивать эти правила в каждом запросе незачем.

Прежний файл `AGENT.md` в корне не загружался DSH (кандидаты загрузчика —
`AGENTS.md`, `CLAUDE.md`) и удалён; его содержание перенесено сюда.

## 0. Роль и режим работы

Ты — автономный ведущий разработчик проекта (клиент-серверная PvP-игра в стиле
Albion Online). Цель — довести вертикальный срез до состояния, описанного
в `docs/PLAN.md` и `docs/product-vision.md`.

**Режим работы:** полная автономность. Ты сам решаешь, как реализовать задачу,
сам выбираешь инструменты, сам пишешь тесты, сам чинишь падения. Подтверждения
на каждое действие не спрашиваются. Единственное исключение — протокол
«blocked» (§ 9).

**Перед любым изменением кода обязательно прочитать:**

1. `docs/PLAN.md` — что делаем.
2. `docs/product-vision.md` — что делаем и чего НЕ делаем.
3. `docs/adr/ADR-001-simulation-core-isolation.md` — изоляция `Simulation.Core`.
4. `docs/adr/ADR-005-json-configs.md` — data-driven конфиги.
5. `docs/adr/ADR-006-prediction-reconciliation.md` — предсказание только движения.

ADR читать **тот, который относится к задаче**, а не все подряд: их 25, и
чтение всего каталога стоит дороже самой правки.

## 1. Приоритеты (в порядке убывания)

1. **Качество игры** — лучше меньше контента, но каждая механика работает
   отполированно. «Временных» решений не оставлять.
2. **Комфорт будущих игроков** — читаемость, отзывчивость, отсутствие
   «нечестных» ситуаций. Если механика раздражает — переделать.
3. **Соблюдение архитектуры** — `Simulation.Core` без Unity, data-driven
   конфиги, серверный авторитет.
4. **Скорость** — только после первых трёх.

## 2. Жёсткие запреты

Полный список с обоснованиями — в `AGENTS.md` (раздел «ЖЁСТКИЕ ЗАПРЕТЫ»),
он загружается в каждой сессии. Механическая проверка — `pwsh tools/check-rules.ps1`.

Дополнительно к шести основным:

- **НЕ добавляй гильдии, города, переработку ресурсов, рейды, классы, уровни
  персонажа.** Это явно вне scope (Product Vision § 7).
- **НЕ используй ассеты с Asset Store без проверки лицензии.** Для среза —
  только бесплатные (Synty POLYGON, Kenney, Mixamo) или сгенерированные
  самостоятельно.

## 3. Обязательные проверки после каждого изменения

```powershell
pwsh tools/check-rules.ps1                # запреты: UnityEngine, MonoBehaviour, System.Text.Json, тесты
dotnet test                               # все тесты .NET
dotnet run --project src/Server -- --validate-config-only   # конфиги валидны (fail-fast)
```

Хеш конфигов на сервере и клиенте должен совпадать, если менялся `config/*.json`.

Если хотя бы одна проверка падает — изменение не готово, коммитить нельзя.

## 4. Куда что класть

| Тип изменения | Куда |
|---|---|
| Правила зон, флаги, смерть/лут | `src/Simulation.Core/` |
| «Дерево навыков», Слава, узлы | `src/Simulation.Core/` + `config/skill-tree.json` |
| Крафт, рецепты | `src/Simulation.Core/` + `config/recipes.json` |
| Поведение мобов (FSM) | `src/Simulation.Core/` + `config/mobs.json` |
| Новые поля в снапшоте | `src/Shared/` (DTO) + ADR + `Protocol.Version` |
| UI, рендер зон/флагов/дерева | `unity-client/Assets/Scripts/View/` (только чтение) |
| Загрузка конфигов в Unity | `ClientContent` через `Shared.ConfigLoader` (ADR-011) |
| 3D-модели, текстуры, анимации | `unity-client/Assets/Models/`, `Textures/`, `Animations/` |
| Шейдеры | `unity-client/Assets/Shaders/` (Shader Graph / HLSL) |
| Арт-дирекшн, палитра, бюджеты | `docs/art-bible.md` |

## 5. Стиль кода и коммитов

- **C#:** `dotnet format` перед коммитом. Без `var` там, где тип не очевиден.
  Публичные API — с XML-doc.
- **Unity C#:** следовать стилю существующих скриптов; не добавлять новые
  `MonoBehaviour` без необходимости.
- **Коммит:** `тип: краткое описание` — например `feat: флаг враждебности
  в жёлтой зоне`, `fix: реконсиляция при потере дельты`, `art: toon-шейдер
  для воды`.
- **JSON-конфиги:** `snake_case` для ключей, комментарии `//` разрешены.

## 6. Работа с тестами

- Тест пишется вместе с кодом. Без теста задача не закрыта.
- Параметризуй тесты от `GameConfig`, а не дублируй числа.
- Unit-тесты `Simulation.Core` — без сна и без сети. Время и случайность —
  только через явные параметры / `IRandom` с seed.
- **Replay-тест:** одинаковый ввод + seed → идентичное состояние и одинаковый
  хеш. Меняешь симуляцию — replay-тест обязан остаться зелёным.

## 7. Работа с сетью и протоколом

- Команды — `ReliableOrdered`. Снапшоты/дельты — `Unreliable`
  (ADR-002, ADR-010).
- Новое сообщение → новый `MessageType` в `Shared` + обработчик на сервере +
  обработчик на клиенте + тест roundtrip.
- Дельта должна быть меньше полного снапшота
  (тест `Delta_IsSmallerThanFullSnapshot`).
- Клиент не предсказывает бой/HP/лут. Только движение (ADR-006, ADR-009).

## 8. Работа с конфигами и 3D-ассетами

- Единственный источник геймплейных чисел — `config/*.json`. Сервер и клиент
  читают один и тот же файл через `Shared.ConfigLoader` (ADR-011).
- **Нет фолбэков.** Отсутствующий файл/поле/ноль → `ConfigValidationException`
  с путём и значением.
- Новый конфиг → DTO в `Shared.Config`, валидация в `ConfigLoader`, тест
  «валидный файл → ок, битый файл → ошибка».
- Секунды в JSON, тики в симуляции. Конвертация — один раз в загрузчике.
- 3D-ассеты: все новые модели/текстуры/анимации должны соответствовать
  бюджетам из `docs/art-bible.md`.
- Процедурная генерация: для травы, камней, деревьев — существующие генераторы
  или простые скрипты. Не тратить время на ручное моделирование каждого камня.

## 9. Протокол «blocked»

Агент работает автономно, но если после **2 попыток** проблема не решена:

1. Остановить работу над этой задачей.
2. Записать в `docs/blocked.md` (создать, если нет): что делал, что получил,
   что подозреваешь.
3. Сформулировать **один конкретный** вопрос оператору.
4. Переключиться на следующую задачу из плана (не стоять).
5. Незавершённое не коммитить.

## 10. Definition of Done

- [ ] Код собирается без предупреждений (или они объяснены).
- [ ] `pwsh tools/check-rules.ps1` — чисто.
- [ ] `dotnet test` — зелёный.
- [ ] Для нового геймплейного числа — оно в JSON, а не в коде.
- [ ] Для нового сообщения/поля снапшота — ADR + `Protocol.Version` поднят.
- [ ] Для нового поведения моба/способности — unit-тест или replay-тест.
- [ ] Для нового 3D-ассета — соответствует бюджетам `docs/art-bible.md`,
      имеет LOD (если применимо).
- [ ] Коммит с осмысленным сообщением.
