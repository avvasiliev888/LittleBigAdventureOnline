# T-008 — конвейер не теряет вердикты и не бьёт ПК при провале

- Дата: 22.11.2026
- Ветка: `agent/T-008`
- Файлы: `tools/tandem/orchestrator.workflow.js`, `tools/tandem/probe-orchestrator.js` (новый, стенд)
- Приоритет: №1 по решению заказчика — до T-006/T-007

> Первый прогон этой задачи через сам конвейер (n=23/24/25) воспроизвёл дефект и был
> зафиксирован отчётом «фича не сделана». Ниже — разбор причины и исправление.

## Дефект

Два провальных прогона T-005 (22.11.2026) вернули одинаковое:

```json
{"done": true, "stopped": null, "tasks": [], "build": {"ok": false}}
```

То есть: код не компилировался, ревьюер выносил FAIL, вердикт в результат не попадал,
а фаза ПК-билда всё равно запускалась. Читая только `done`, прогон выглядел успешным.

## Причина (найдена стендом, не догадкой)

В исходном оркестраторе блок ревью стоял **после** `while`-цикла попыток исполнителя, на
уровне `for` по задачам. Поэтому `continue` в ветке `review.verdict === "FAIL"` продолжал
**внешний** цикл по задачам, а не повторял исполнителя:

1. задача покидалась без записи в `results` (отсюда `tasks: []`);
2. `stopped` оставался `null`;
3. условие финальной фазы `if (!stopped)` было истинным → ПК-билд запускался;
4. `done = !stopped` давало `true`.

Стенд `tools/tandem/probe-orchestrator.js` воспроизвёл это без единого платного вызова:

```
=== review-fail ===
agents: T-PROBE executor #1, T-PROBE reviewer, build-windows, report
done: true | stopped: null | tasks: []
```

## Что сделано

Оркестратор переписан: исполнитель, ревью и гейт теперь в одном цикле задачи, поэтому
FAIL по ревью действительно повторяет исполнителя. Добавлены инварианты:

| № | Инвариант | Реализация |
|---|---|---|
| 1 | Каждая задача попадает в результат | `results.push` в конце цикла задачи + добор `status: "missing"` для пропущенных |
| 2 | ПК-билд только при полном успехе | `runOk` → иначе `buildInfo = {ok:false, skipped:true}` |
| 3 | `done` не врёт | `done = stopped === null && tasks.length > 0 && results.length === tasks.length && все "pass"` |
| 4 | Ревью-FAIL повторяет исполнителя | `continue` внутри цикла задачи |
| 5 | Журнал решений для разбора | массив `decisions` в результате + файл `docs/reports/logs/tandem-*.json` пишет агент отчёта |

Дополнительно: пустой список задач больше не считается успехом (`done=false`), отчёт пишется
и при провале (раньше провал вообще не разбирался), чекбоксы плана переключаются только для
задач со статусом `pass`.

## Проверка

### Стенд (6 сценариев, 0 платных вызовов)

| Сценарий | До правки | После правки |
|---|---|---|
| всё проходит | `done=true`, билд | `done=true`, билд — без изменений |
| ревью FAIL | **`done=true`, `tasks=[]`, билд** | 4 попытки + отладчик, `done=false`, `needs-human-debug`, билд пропущен |
| ревью вернуло null | `review-error` | `review-error`, билд пропущен |
| гейт Unity FAIL | `unity-fail` | `unity-fail`, билд пропущен |
| пустой список задач | `done=true` | `done=false` |
| бюджет исчерпан | билд пропущен | билд пропущен |

### Живой прогон (заведомо падающая задача T-900, 1 платный вызов)

Задача намеренно ломала `src/Shared/MiniJson.cs` (`CS0103`), чтобы гарантировать красные гейты:

```json
{"done": false, "stopped": "gate-fail",
 "tasks": [{"id": "T-900", "status": "gate-fail", "attempts": 2}],
 "build": {"ok": false, "skipped": true},
 "decisions": [{"attempt": 1, "decision": "retry:gates"},
               {"attempt": 2, "decision": "retry:gates"},
               {"attempt": 2, "decision": "stop:gate-fail"}]}
```

Чекбоксы `docs/plan_for_gemma.md` не тронуты (проверено `git status`), поломка откачена,
ветка `agent/T-900` удалена.

## Что осталось

- Зелёный живой прогон успешной задачи в этом сеансе не делался: успешный путь покрыт
  стендом (`all-pass`), а end-to-end подтвердится на следующей реальной задаче (T-006).
- Стенд `probe-orchestrator.js` оставлен в репозитории как постоянный регрессионный тест
  оркестратора: он ловит именно этот класс ошибок без расхода платных вызовов.
- Журналы `docs/reports/logs/tandem-*` в `.gitignore` — это локальные логи прогонов.

## Расход

Платных вызовов за задачу: 1 (n=26, `architect`/`report`); прогон T-008 через конвейер
потратил ещё 3 (n=23/24/25) на отчёт о провале, который зафиксировал дефект.
