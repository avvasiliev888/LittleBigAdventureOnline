# План: постоянная точка бега и непрерывный бой по фиксированной цели

**Статус:** согласован 20.11.2026, к исполнению не начат.
**Предыдущие документы:** `docs/combat-facing-plan.md` (поворот, подход, лук),
`docs/warrior-animation-ledger.md` § 10–11 (что уже сделано и что нельзя ломать).

---

## 1. Что сломалось и почему

Заказчик после билда `23:08`:

> «Теперь сломался бег к указанной цели. Должно работать так: Я кликнул мышью
> ЛКМ или ПКМ, и персонаж побежал к этой точке, и должен бежать пока не добежит
> или пока не получит другую команду.»

**Причина — моя правка предыдущего захода.** Сброс точки при отпускании кнопки
мыши существовал и раньше, но стоял **после** раннего выхода
`if (!left && !right) return;` — то есть был мёртвым кодом и не выполнялся
никогда. Я перенёс его выше выхода, и он стал рабочим: точка умирает на
отпускании кнопки, быстрый клик даёт один-два кадра бега.

Отсюда правило на будущее (см. § 8): **мёртвый код нельзя «оживлять» молча.**
Если строка никогда не исполнялась — это первый повод усомниться, а не первым
делом починить её.

## 2. Решения заказчика (дословно)

| Вопрос | Решение |
|---|---|
| Сколько ударов по цели | **Повторять удар каждый раз, когда готов кулдаун**, пока цель жива |
| Что отменяет | Клик ЛКМ/ПКМ в землю, нажатие WASD, новое нажатие Пробела по другой цели |
| Погоня | **Бежать, пока цель жива и находится в мире — без ограничения** |
| Цель умерла | **Остановиться и стоять**, ждать новой команды |
| Точка недостижима | **Стоять на месте, точка остаётся до новой команды** |
| Преследование в кулдауне | **Преследовать и в кулдауне** — держаться в радиусе |
| Лук | **Остановиться на радиусе лука (8 м) и стрелять серией** |

**Ключевое уточнение заказчика, определяющее всю модель:**

> «Атака должна продолжаться непрерывно, если цель находится в радиусе
> поражения оружия, даже если отдана команда бежать к какой-то точке. Новая
> команда отменяет бег к цели, которая за пределами радиуса, но не отменяет
> продолжение атаки цели, которая уже в радиусе поражения. Атака отменится
> только, если новые команды вывели персонажа из радиуса поражения текущей
> цели или была назначена новая цель для атаки.»

---

## 3. Целевая модель: две независимые шины

Главная ошибка прежней реализации — **один канал команд на всё**. Атака
и движение боролись за право вернуть команду из `TryReadCommand`, поэтому
приходилось гасить одно ради другого. Теперь это два независимых состояния.

### Шина A. Движение

| Правило | Значение |
|---|---|
| Зарождается | Клик ЛКМ/ПКМ в землю, либо нажатие WASD |
| Живёт | **До прибытия** (`distance <= mouseMoveThreshold`) **или другой команды** |
| Отпускание кнопки мыши | **НЕ отменяет.** Точка замораживается на месте клика |
| Удержание кнопки | Обновляет точку каждый кадр (удержание = ведение курсором) |
| Отменяется | Новым кликом (замена), нажатием WASD, смертью/респавном, кликом по HUD, смертью цели боя |

### Шина B. Бой (зафиксированная цель)

| Правило | Значение |
|---|---|
| Зарождается | **Фронт нажатия** Пробела/кнопки атаки — цель читается **один раз** (по курсору) |
| Живёт | Пока цель **жива, в мире и в радиусе** либо по ней идёт погоня |
| Удары | Повторяются автоматически, каждый раз когда кулдаун готов и клип доиграл |
| Отпускание Пробела | **НЕ отменяет.** Бой идёт, пока цель жива |
| Погоня | Включается, если цель **вне** радиуса; идёт без ограничения по времени и расстоянию |
| Погоня отменяется | Любой новой командой движения (клик или WASD) |
| Бой отменяется | Смертью цели · уходом из радиуса после отмены погони · новым нажатием Пробела (новая цель) · исчезновением цели из снапшота · смертью игрока |

### Приоритет внутри тика

`_lockedTarget != 0` **сильнее** ручного движения только пока идёт погоня.
Как только игрок дал команду движения, погоня снимается и ручное движение
получает управление — но сама цель остаётся, и удары продолжаются, пока
персонаж не выйдет из радиуса.

## 4. Состояния и переходы

```
            клик в землю
  [Стоит] ────────────────► [Бежит в точку]
     ▲                            │  прибыл / WASD / новый клик
     │                            ▼
     │                        [Стоит]
     │
     │  Пробел (цель вне радиуса)
     ├───────────────► [Погоня] ──── дошёл до радиуса ───► [Бой]
     │                    │                                   │
     │   клик/WASD        │                                   │ удары по кулдауну
     └────────────────────┴───────────────────────────────────┘
                          цель умерла / вышли из радиуса → [Стоит]
```

**Определение радиуса.** `reach = range - approachSlack` — тот же расчёт, что
уже используется в `TryApproachStep`. Радиус берётся из `config/abilities.json`
через `ClientPrediction.AbilityRange` (меч — **3 м**, лук — **8 м**),
`approachSlack` — из настроек (`0.6`).

**Почему лук работает сам по себе.** Разница только в радиусе: с мечом погоня
доводит до **2,4 м**, с луком останавливается на **7,4 м**. Отдельной ветки для
лука не нужно — она уже есть в конфиге.

## 5. Что менять

### 5.1. `unity-client/Assets/Scripts/Input/UnityInputSource.cs` (основное)

**Убрать:**
- `_abilityPressed` — понятие «нажатие ждёт отправки» больше не существует,
  его место занимает `_lockedTarget`.
- `StoppedTicksLimit` остаётся, но применяется к повторным ударам.

**Добавить:**
- `_engagedTarget` (`uint`) — зафиксированная цель, `0` = боя нет.
- `_chaseActive` (`bool`) — идёт погоня; снимается командой движения.
- `public uint EngagedTarget => _engagedTarget;` — чтобы `ClientRuntime` знал,
  кого показывать в `TriggerAttack` (сейчас он берёт `_lastAbilityTarget`,
  который обновляется слишком часто).
- `private void ReleaseEngagement(bool clearDestination)` — единая точка выхода
  из боя. `clearDestination: true` для «цель умерла» → стоим.

**Восстановить:**
- `PollMouseDestination`: **не сбрасывать** `_destinationActive` при отпускании
  кнопки; ставить точку на фронте клика, обновлять при удержании.

**`TryReadCommand` — новый порядок веток:**

```
1. scripted-команда (тестовая подложка, не трогаем)
2. если цель зафиксирована и мертва → ReleaseEngagement(clearDestination: true)
3. если цель зафиксирована:
     a. вне радиуса и погоня идёт   → шаг погони (MoveCommand), return
     b. вне радиуса и погони нет    → ReleaseEngagement(false), идти дальше
     c. в радиусе:
          - кулдаун готов, клип доиграл, тело стоит → AbilityCommand(_engagedTarget)
          - тело скользит → тик остановки (не больше StoppedTicksLimit)
          - кулдаун идёт → провалиться к движению (можно бежать, удары сами
            пойдут по готовности; за радиусом отпустит по пункту 3b)
4. клип атаки играет → команды нет (ноги в клипе, иначе «плывёт»)
5. ручное движение: WASD (снимает точку) → точка мыши
```

**Отмена погони** — в `PollFrame`, там же где сейчас: свежий клик в мир и
**новое** нажатие WASD вызывают `CancelChase()`. Новое нажатие Пробела
перезаписывает `_engagedTarget`.

### 5.2. `src/Client.Network/ClientPipeline.cs`

- `public bool TryGetEntity(uint id, out EntityState entity)` — поиск по
  `_lastSnapshot.Entities`. Нужен, чтобы отличить «цель умерла» от «цель
  вышла из снапшота»: сейчас в клиенте такого доступа нет.
- `FindNearestEntityTo` не трогать — работает.

### 5.3. `unity-client/Assets/Scripts/Bootstrap/ClientRuntime.cs`

- `Update`: `_view.TriggerAttack(_input.EngagedTarget)` вместо
  `_lastAbilityTarget`. Иначе при повторных ударах замах покажется по старой
  цели: `_lastAbilityTarget` переустанавливается при каждом вызове
  `ResolveAbilityTarget`.
- `ResolveAbilityTarget` остаётся — его вызывает ввод на фронте нажатия.

### 5.4. `unity-client/Assets/Scripts/View/UnityView.cs`

Не меняется. `FaceAttackTarget` вызывается на каждый `TriggerAttack`, то есть
на каждый повторный удар — доворот отработает заново. Это и нужно: цель
двигается между ударами.

## 8. Ловушки — не повторять

1. **Не возвращать сброс точки на отпускании кнопки.** Именно это сломало бег
   в билде `23:08`. Точка живёт до прибытия или новой команды.
2. **Повторные удары привязывать к `_engagedTarget`, а не к удержанию клавиши.**
   Удержание клавиши — источник прошлого бага «атака срабатывает повторно».
   Разница: теперь повтор управляется целью, и он прекращается вместе с боем.
3. **Цель читать только на фронте нажатия.** Перечитывание на ходу — прошлый
   баг «перенаведение на другую цель».
4. **Мёртвый код не оживлять молча.** Строка после раннего `return` не
   исполняется; прежде чем «чинить», понять, зачем её туда положили.
5. **Атака и движение — разные шины.** Не сводить их обратно в один флаг:
   вся эта задача выросла из того, что один канал не может выразить
   «бежать в точку И бить того, кто рядом».
6. **`_lockedTarget` нельзя сбрасывать при отпускании Пробела.** Бой идёт,
   пока цель жива, — это прямое требование заказчика.
7. **Один слой анимации.** Во время клипа удара команды движения не
   отправляются — иначе тело «плывёт» с застывшими ногами.
8. **Не запускать игру и сборку без прямой просьбы.**

## 9. Открытые риски

- **Стукотня «бег ↔ удар».** Если цель в радиусе, а игрок ведёт персонажа
  мимо, каждый готовый кулдаун будет вставлять тик остановки: бег станет
  рваным. Допустимо (так задумано), но если заказчик сочтёт неприятным —
  отключается одним флагом «не бить на ходу».
- **Моб в радиусе, но за стеной.** Клиент не знает про геометрию: будет бить
  сквозь стену. Сервер решит по своим правилам.
- **Погоня без ограничения.** Если цель быстрее персонажа, персонаж бежит за
  ней, пока игрок не даст команду. Это выбор заказчика, не дефект.
