# Unity-проект (клиент)

Здесь живёт Unity-клиент. Правила (ADR-001, ADR-006):

- авторитетной игровой логики в `MonoBehaviour` нет — только отображение и ввод;
- `Simulation.Core` подключается к клиенту **только** через `Bootstrap` и `Prediction`;
- `*.meta` трекаются git, бинарные ассеты > 100 KB — через Git LFS.

Версия редактора фиксируется в `ProjectSettings/ProjectVersion.txt` (Unity 6.3 LTS, 6000.3.x).

## Как запустить (M6)

1. Собрать плагины (netstandard2.1 → `Assets/Plugins/Albion`, каталог не коммитится):

   ```
   pwsh -File tools/unity/build-plugins.ps1
   ```

2. Запустить сервер в отдельном терминале из корня репозитория:

   ```
   dotnet run --project src/Server -c Release -- --udp 9050
   ```

3. Открыть `unity-client` в Unity 6.3, открыть сцену `Assets/Scenes/Arena.unity` (M10), нажать **Play**.

Клиент запускается сам (`ClientRuntime` через `RuntimeInitializeOnLoadMethod`): подхватывает сцену
арены (пол, колонны, камни, кристаллы, свет, Volume) или, если сцены нет, создаёт окружение сам;
подключается к серверу, шлёт `MoveCommand` по WASD/ПКМ и двигает стилизованных персонажей
по интерполированным снапшотам (лаг отображения 2 тика = 100 мс).

С M10.7 сервер спавнит тренировочный манекен (entity 2, 100 HP) в `(4, 0, 0)`, в двух метрах от
первого игрока. Манекен — тот же Warrior, медленно патрулирует по X со скоростью 1 m/s и служит
целью для Space/ЛКМ; его Hit/Death/respawn идут обычным snapshot/delta-путём.

Настройки подключения:

- переменные окружения `ALBION_SERVER_HOST`, `ALBION_SERVER_PORT`;
- аргументы командной строки `-serverHost 127.0.0.1 -serverPort 9050` (для билда).

## Предсказание и плохая сеть (M7)

Клиент предсказывает движение игрока по `moveSpeed` из HelloAck и реконсилирует его по `ServerAck`
(ADR-009). В HUD вторая строка:

```
prediction: reconciles=0 | lastError=0.000 | pos=(3.42, 0.18) | unacked=0
```

- `reconciles` — сколько раз реально сработала реконсиляция (на стабильной сети остаётся 0);
- `unacked` — сколько команд ещё не подтверждено сервером;
- каждая реконсиляция пишется в консоль Unity: `ClientRuntime: реконсиляция tick=… error=…`.

Имитация плохой сети включается флагами сервера (задержка в обе стороны + потери снапшотов):

```
dotnet run --project src/Server -c Release -- --udp 9050 --delay 100 --loss 20
```

Ожидаемое поведение: движение отзывчивое (предсказание), редкие плавные подтягивания при коррекциях,
`reconciles` растёт только при реальных расхождениях.

Как рисуются игроки (M7):

- **локальный игрок** — без задержки буфера: позиция сразу следует за предсказанием, между тиками
  20 Гц экстраполируется по времени (dead reckoning) по скорости из отправленной команды, коррекции
  реконсиляции гасятся визуальным оффсетом (~120 мс), поэтому управление ощущается мгновенным,
  без телепортов; сэмплы подаются каждый клиентский тик, джиттер сети на тайминг не влияет;
- **удалённые игроки** — через буфер снапшотов с задержкой 2 тика (100 мс) и интерполяцией, чтобы
  ехали плавно даже при потерях и джиттере.

## Дельта-снапшоты и пропуски (M8)

С M8 сервер не дублирует неизменённые поля: после первого полного снапшота каждый тик приходит
`Delta` (ненадёжно) с базовым тиком, а полный `Snapshot` — только когда базы у клиента быть не может
(первое подключение, ответ на `FullSnapshotRequest`, разрыв). Формат и обоснование — ADR-010,
протокол v4.

В HUD первая строка показывает:

```
Albion: connected | snapshots: 412 (delta 409, fullReq 2) | WASD/ПКМ — движение, Space/ЛКМ — способность
```

- `delta` — сколько дельт успешно применено; на стабильной сети растёт каждый тик;
- `fullReq` — сколько раз клиент потерял базу (потеря пакета) и запросил полный снапшот. При `--loss 20`
  это единицы-десятки за минуту, при стабильной сети — 0 после первых снапшотов;
- если дельта не применяется (нет базы), клиент не «залипает»: запрос полного идёт по надёжному
  каналу с кулдауном 0.3 с, восстановление занимает 1–2 тика.

Проверить объём вживую:

```
dotnet run --project src/Server -c Release -- --udp 9050
dotnet run --project tools/test-client -c Release -- 127.0.0.1 9050 10
```

в итоговой строке — `снапшотов=N (дельтами M)` и `запросов полного снапшота=0`.

Клиент хранит историю 16 последних снапшотов (0.8 с); при задержке больше этого окна дельты будут
терять базу и клиент перейдёт на полные снапшоты — корректно, но дороже по трафику.

## Data-driven контент (M9)

Клиент читает тот же JSON, что и сервер, тем же загрузчиком из `Shared` (ADR-011):

- `tools/unity/build-plugins.ps1` копирует `config/actors.json` и `config/abilities.json` в
  `Assets/StreamingAssets/Config/` (каталог генерируемый, в git не попадает);
- `ClientRuntime` грузит его при старте; при ошибке в HUD видно `config error: …` и клиент не
  подключается (тихого фолбэка на константы нет);
- в HUD появились `cfg: <первые 8 символов SHA-256>`, `hp: X/Y`, `res: X/Y`, `cd: N тиков`,
  `range: R`, а хеш должен совпадать с серверным (`config: … hash: …` в логе сервера).

Что берётся из конфига:

- скорость предсказания — `actors[].moveSpeed`;
- радиус и кулдаун — `abilities[].range` / `cooldownSeconds` (в тиках `ceil(sec/0.05)`);
- `maxHp` актора для HUD; текущий HP — из снапшота;
- `maxResource` и `resourceRegenPerSecond` — запас и восстановление ресурса на сервере; HUD показывает
  `res` из снапшота. Без регенерации 10 ударов по 10 ресурса навсегда блокировали способность
  (`NotEnoughResource`), поэтому у игрока `5/с` — ровно стоимость одного удара за кулдаун.

Space/ЛКМ — авто-атака: пока клавиша/кнопка удерживается, клиент отправляет `AbilityCommand`, как
только кулдаун равен 0 **и текущий Attack-клип доиграл**; отпускание прекращает новые команды. Пока
`IsAttackPlaying == true` или кулдаун ещё идёт, команда способности не отправляется и клип не
перезапускается — вместо неё уходит `MoveCommand`, поэтому WASD/ПКМ продолжают двигать персонажа во
время атаки и кулдауна. Флаг удержания дожидается готовности.

ПКМ — движение к курсору: луч из камеры через `Input.mousePosition` пересекается с плоскостью `Y=0`,
вектор до точки уходит в `MoveCommand` каждый клиентский тик, поэтому персонаж меняет направление
вслед за курсором. Если до точки ≤ 0.5 м, команда не отправляется. WASD и ПКМ можно комбинировать:
направления складываются (W+ПКМ — диагональ), `Ctrl` применяет шаг к обоим.

Цель — ближайшая **живая** сущность, а если живых нет — ближайшая мёртвая (удар по ней — легальный
miss без урона, но с кулдауном). `TargetId = 0` остаётся только для пустого мира. M10.8: **любая
валидная активация тратит кулдаун и ресурс** — удар по мёртвой, дальней или неизвестной цели тоже
считается swing/miss, но сервер не наносит урон. M10.9: отказ сервера **не обнуляет** локальный
кулдаун: сохраняется текущий остаток, на границе кулдауна — 1 тик, при настоящем отказе — полный
штрафной кулдаун. Урон по себе запрещён (`SelfTarget`), поэтому Attack не прерывается собственным Hit.
В HUD сразу виден кулдаун в относительных тиках (`cd: 40` → 0), сервер подтверждает его в снапшоте.
Пока кулдаун идёт, нажатие игнорируется локально, но движение продолжается; во время активного Attack
повторный Space/ЛКМ не перезапускает клип с первого кадра. HP предсказывается только сервером —
локального урона в клиенте нет. Цель по умолчанию — манекен M10.7. Проверка data-driven:

1. измените `config/abilities.json` (`cooldownSeconds` 2 → 6, `damage` 25 → 5) и `config/actors.json`
   (`moveSpeed` 4 → 6);
2. перезапустите сервер, снова запустите `pwsh -File tools/unity/build-plugins.ps1`;
3. перезапустите Play (код не перекомпилируется): движение быстрее, кулдаун ~120 тиков, урон 5,
   `cfg:` хеш другой.

## URP, стилизация и два профиля качества (M10)

Рендер-пайплайн — URP 17.3.0 (сам URP поставляется с Unity; registry-зависимостям на чистой машине без UPM-кэша может понадобиться сеть, ADR-012).
Ассеты и сцена генерируются редакторскими скриптами и лежат в git:

- `Albion/Rendering/Setup URP` (`Assets/Editor/AlbionUrpSetup.cs`) — два renderer data и два
  `UniversalRenderPipelineAsset`: `Assets/Resources/Rendering/UrpDesktop.asset` (deferred, HDR,
  SMAA камеры (без MSAA в deferred), мягкие тени 2048/60 с двумя каскадами, GPU Resident Drawer,
  Bloom+Vignette+ColorAdjustments+ACES Tonemapping) и `UrpMobile.asset`
  (forward, без HDR/MSAA/пост-обработки, render scale 0.8, тени выключены);
- `Albion/Rendering/Validate URP` — проверяет профили, shadow/depth-проходы, ошибки шейдеров и
  сохранённые subassets Volume (не только наличие файла профиля);
- `Albion/Rendering/Capture and Test Arena` (`AlbionRenderProbe.Run`) — реальный GPU-рендер в
  `Builds/visual-check`: desktop/full, fog-off, shadows-off, post-off, light-changed и mobile/fog-off,
  PNG + `metrics.json`. Требует сохранённых сцен и выхода из Play; batchmode — без `-nographics`.
  Сравнивает пиксели с повторным кадром для оценки шума, отдельно требует затемнения на полу
  от падающих теней. Это регрессия работоспособности эффектов, не замена визуального Human-Gate;
- `Albion/World/Rebuild Arena` (`Assets/Editor/AlbionWorldBuilder.cs`) — сцена `Arena.unity`
  с LODGroup (8 колонн, 6 камней), static-флагами и occlusion culling;
- `Albion/Build/Desktop|Mobile` (`Assets/Editor/AlbionBuild.cs`) — две сборки в `Builds/desktop`
  и `Builds/mobile`; mobile получает символ `ALBION_MOBILE_DEFAULT`.

Профиль выбирается в рантайме (`Assets/Scripts/Rendering/QualityProfile.cs`): `ALBION_QUALITY`,
аргумент `-quality desktop|mobile` или дефолт сборки. В HUD видно `profile: desktop|mobile` и
сглаженный `fps`; раз в 10 секунд FPS пишется в лог (`[fps] profile=… avg=…`).

Стилизация: `Assets/Shaders/ToonLit.shader` (двухцветная рампа, мягкая тень, rim, контур
inverted hull; проход `UniversalForwardOnly` работает и в deferred) и `ToonGround.shader`
(шахматка без текстур). Оба имеют ShadowCaster/DepthOnly и fog-варианты с MixFog; fog берётся
из RenderSettings, а Bloom/цветокоррекция/Tonemapping — из сохранённых Volume overrides.
Кристаллы имеют HDR-emission для Bloom. Окружение пока процедурное; персонажи заменены на
импортированный оператором Warrior (см. ниже). Наличие occlusion-ассета не доказывает успешный bake:
Unity batchmode ранее сообщал `Occlusion culling bake unsuccessful`; при необходимости повторите
`Window/Rendering/Occlusion Culling → Bake` в редакторе.

### Warrior: настройка в Unity и проверка

1. После клонирования выполните `git lfs pull`, соберите плагины и откройте проект в Unity 6000.3.28f1.
2. Выберите `Assets/Resources/Characters/WarriorVisual.asset` в Project. В Inspector поле **Prefab**
   должно ссылаться на **`Assets/dRealWarriorFantasyCharacter/Prefabs/Warrior.prefab`**.
   **Height = 1.85**, **Yaw = 0** (Humanoid forward +Z), **Ground Offset = 0**. Конфигурация уже сохранена в git;
   меню **Albion → Characters → Configure Warrior Visual** восстанавливает ссылку при необходимости.
   Сам vendor-prefab перемещать в Resources не нужно: Resources-конфигурация включает его зависимости в сборку.
3. Материалы `M_Warrior_Chainmail` и `M_Warrior_Weapons`: Shader **Universal Render Pipeline/Lit**,
   исходные Albedo/Base Map, Normal и Metallic/Smoothness сохранены. Конвертировать их из Standard не требуется.
   Для двух используемых `*_MetallicSmoothness` текстур **sRGB (Color Texture) выключен**;
   albedo остаётся sRGB, normal — Texture Type **Normal map**. На рендере нет magenta.
4. **Albion → Characters → Validate Warrior Visual** проверяет точный prefab, материалы, высоту/опору,
   включённый Animator с root motion **OFF**, отключённые коллизии, Idle/Walk/Run, Attack/Hit/Death,
   prediction, разворот, отсутствие дрейфа root, интерполяцию удалённых при 30/60/144 FPS и респавн.
   **Albion → Rendering → Capture and Test Arena** добавляет двух Warrior через настоящий UnityView;
   сохраняет desktop/mobile, кадры без персонажей, крупные планы, Attack/Death и метрики в `Builds/visual-check`.
   Нужен GPU, не используйте `-nographics`. В batch: `-executeMethod Albion.Editor.AlbionCharacterSetup.ConfigureAndVerify`.
5. Запустите сервер и Play. WASD/ПКМ двигают сетевой root (ПКМ — к курсору по плоскости Y=0, мёртвая
   зона 0.5 м); **Ctrl** — реальный шаг 1.5 m/s (меньшая величина команды, без изменения протокола).
   ЛКМ и Space запускают одну и ту же авто-атаку. Масштаб/offset только у дочернего
   `Warrior Calibration` вне Animator hierarchy, поэтому анимация не перезаписывает размер и опору.
   Тело — живой SkinnedMeshRenderer, Animator enabled, **Apply Root Motion OFF**. Тестовое BakeMesh
   используется только при калибровке/проверке, не для показа. Runtime сокеты оружия перепривязаны
   к Humanoid LeftHand/RightHand с сохранением исходной rest-pose посадки; vendor-prefab не изменён.
   При HP=0 один раз проигрывается Death и поза удерживается до респавна; материалы не перекрашиваются.
6. `Resources/Characters/WarriorLocomotion.controller`: float **Speed**; Idle при Speed ≤ 0.1,
   при Speed > 0.1 — Locomotion (1D Walk/Run, пороги 1.5 и 4 m/s), переходы 0.1 s без exit time.
   Attack/Hit/Dead — отдельные one-shot states; WarriorVisual включает их по факту старта способности,
   падению HP и смерти, а после exit-фазы возвращает Idle/Locomotion. Повторный Space/ЛКМ во время удара
   игнорируется до exit-фазы текущего swing (проверка `IsAttackPlaying`), а не перезапускает клип;
   Death имеет приоритет.
   Скорости клипов откалиброваны по исходной averageSpeed. Локальный Speed и поворот берутся
   **из velocity локального prediction**, не из reconciliation/render displacement. При остановке
   остаётся последнее направление; A/D разворачивают visual по движению, не сетевой root.
   У удалённых Speed берётся из интерполированного displacement/dt: spawn, respawn, catch-up,
   смена источника, невалидный/нулевой dt и correction > 2 m/network tick сбрасывают его в Idle.
7. GPU probe дополнительно сохраняет `warrior-{desktop|mobile}-{idle|walk|run-00|run-01|run-02|attack-00|attack-01|death|left|right|stopped}.png`
   и 30 кадров `*-cycle-00..29.png` полного Run для визуальной проверки; `metrics.json` проверяет
   реальные межкадровые изменения Attack, Death и Run. Цикл проверяется с неподвижным сетевым root
   намеренно — для доказательства отсутствия root-motion дрейфа. Игровое перемещение остаётся у prediction/interpolation.

**Известное состояние исходного ассета:** в правой руке prefab одновременно активны меч и топор,
в левой — щит; это сохранено без редактирования vendor-prefab. Выбор оружия и переработка окружения
в M10.5 не входят. В самом dReal Warrior FBX анимационных клипов нет. Из уже скачанного Asset Store
пакета **Female Warrior Princess (All Star Characters)** взят минимальный совместимый мужской набор:
`AllStarCharacterLibrary/Models/RootAnimsMale/BaseMale.fbx` (общий reference-pose Avatar) и
`BaseMale@1HIdle.fbx`, `BaseMale@1HWalkF.fbx`, `BaseMale@1HCombatRunF.fbx`,
`BaseMale@1HAttack.fbx`, `BaseMale@1HPain.fbx`, `BaseMale@1HDeathA.fbx` (3 looped locomotion и
3 one-shot combat Humanoid клипа). Они ретаргетятся на исходный Warrior Avatar; весь анимационный
пакет не импортируется. Меню Configure настраивает Copy From Other Avatar, loop/root-lock и controller;
события клипов убраны. Attack/Death выбраны как один короткий swing и падение назад; другие DeathB/C
и step-клипы не импортированы.
Asset Store «бесплатный» не означает CC0: исходники остаются в приватном проекте, не предназначены
для самостоятельной перепубликации (лицензия Unity Asset Store, не отдельная свободная библиотека).
В репозиторий включён только runtime-набор зависимостей выбранного prefab; остальные импортированные
демо/варианты остаются локальными файлами оператора. M10 по-прежнему требует визуальный Human-Gate.

## HP/мана-бары и индикатор кулдауна (M10.8, M10.10.2)

- `HealthBar` — world-space полоски над головой у **каждой** сущности (локальный игрок, манекен,
  удалённые игроки): тёмная подложка и красное заполнение HP. Сразу под HP, той же шириной 0.9,
  тонкая (0.045) синяя полоска маны с такой же тёмной подложкой. Обе не скрываются при полном/нулевом
  значении, поэтому пропорция читается всегда; bar всегда развёрнут к камере.
- Мана — `entity.Resource / entity.MaxResource` из снапшота (`SetResource`), обновляется на каждом
  снапшоте; у манекена она полная, у игрока видно расход и регенерацию.
- `CooldownHud` — круглая иконка меча внизу по центру. Готовая способность — золотая; после активации
  иконка бледно-серая и закрашивается снизу вверх по `CooldownRemainingTicks` из prediction, который
  реконсилируется серверным `CooldownUntilTick`.
- Реализация без Canvas/UGUI: HP+мана — четыре quad-меша с URP Lit (шейдер уже включён материалами
  Warrior), HUD — две сгенерированные текстуры в `OnGUI`. Новых per-frame аллокаций и Canvas rebuild
  нет; FPS-бюджет не меняется.

## Управление мышью (M10.10)

- **ПКМ (удержание)** — бег к курсору. Камера пускает луч через `Input.mousePosition`; пересечение с
  плоскостью `Y=0` даёт точку, `точка − Prediction.Position` нормализуется в `MoveCommand` каждый
  клиентский тик. Курсор можно вести — направление меняется на ходу. Ближе 0.5 м команда не
  отправляется.
- **ЛКМ (удержание)** — та же авто-атака, что Space: `IsAbilityReady`, `IsAttackPlaying`, кулдаун,
  движение во время атаки/кулдауна, авто-повтор после готовности.
- **Комбинации:** WASD + ПКМ складываются (диагональ), противоположные направления гасятся; Space +
  ПКМ = бег и удары; Space + ЛКМ не дублируют удар. `Ctrl` применяет шаг и к мыши.
- **Курсор:** `Application.runInBackground=true`, `Cursor.lockState=None`, `Cursor.visible=true` —
  курсор не захвачен. В HUD: `WASD/ПКМ — движение, Ctrl — шаг, Space/ЛКМ — способность, 1/2 — оружие`.

## Оружие (M10.11)

- Импортированный Warrior-префаб содержит **и меч, и топор** под правым hand socket. Раньше оба меша
  были видны одновременно; теперь `WeaponVisuals` при спавне оставляет только меч.
- **1** — меч, **2** — топор (основная и numpad-клавиши). Ровно один GameObject оружия активен;
  второй скрыт, а не удалён, поэтому переключение мгновенное и обратимое.
- Переключение **клиентское**: `AbilityCommand`, урон, радиус и сервер не меняются; протокол не
  затронут. Выбор локален для игрока, удалённые игроки остаются с мечом.
- Атака использует один humanoid-клип `1HAttack`; оружие — дочерний объект hand socket, поэтому
  активный меч/топор следует за анимацией удара. Это проверяет
  `AlbionCharacterSetup.ValidateWeaponAnimation`: позиция и меча, и топора меняется во время Attack.

## Ресурс и регенерация (M10.10.1)

Удар стоит 10 ресурса, максимум 100. Раньше регенерации не было: после 10 ударов сервер отвечал
`NotEnoughResource`, и манекен после респавна оставался с 75 HP — выглядел «бессмертным». Теперь у
игрока `resourceRegenPerSecond = 5.0` в `actors.json`: за 2 секунды кулдауна возвращается ровно
стоимость удара. Ресурс восстанавливается на сервере до способности, дробится по тикам без потерь
(`ResourceRegenRemainder`), не регенерирует у мёртвых и обнуляется при респавне. HUD показывает
`res: X/Y` из снапшота. Тест `RepeatedCasts_DoNotStarveAndKeepDamagingAfterRespawn` прогоняет 12
ударов с респавном.

## Ограничения M6–M10

- Рендер-пайплайн — URP; персонаж Warrior подключён, но окружение всё ещё из простых форм.
  Это не означает принятия визуального качества M10 оператором.
- Тестов Unity Test Framework в проекте нет (пакет не установлен); smoke-тесты клиента — xUnit
  `ClientPipelineTests` в `src/Tests` (подключение → ввод → снапшоты → отрисовка, предсказание
  и сходимость при задержке/потерях).
- Предсказывается движение и кулдаун способности (кулдаун из конфига); урон, ресурсы и HP — серверные.
- Таргетинга способности мышью нет: Space/ЛКМ целятся в ближайшую живую сущность, при отсутствии живых —
  в ближайшую мёртвую. Мёртвая/дальняя цель — легальный miss с кулдауном, а не ошибка клиента;
  `TargetId = 0` отправляется только когда в мире вообще нет других сущностей. Авто-атака удержанием
  Space/ЛКМ останавливается при отпускании, а `IsAttackPlaying` не даёт перезапускать клип;
  WASD/ПКМ при этом продолжают двигать персонажа.
- Локальный кулдаун — жёсткий: серверный отказ не сбрасывает его в 0; на границе кулдауна ждём один
  тик, при настоящем отказе (self/resource/cooldown) ставим полный штрафной кулдаун.
- Mobile-профиль без теней (ради FPS ≥ 30); если нужны — включим в `UrpMobile.asset` и замерим.
- GPU Resident Drawer включается только на D3D12-железе; иначе URP предупреждает и продолжает работу.
