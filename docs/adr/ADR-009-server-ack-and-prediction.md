# ADR-009. ServerAck, скорость в HelloAck и предсказание без копии конфигурации

**Статус:** предложен (ожидает Human-Gate M7)
**Дата:** 2026-11-09
**Связано:** ADR-004 (формат и версии), ADR-006 (prediction/reconciliation), ADR-008 (запись сущности), `docs/prototype-plan.md` (M7)

## Контекст

ADR-006 требует от клиента предсказания движения и реконсиляции «откатом, а не телепортом», при этом
предполагает, что клиент локально исполняет `Simulation.Core` с тем же `GameConfig` и получает
`LastProcessedClientTick` внутри снапшота. При реализации M7 выяснились два ограничения:

1. **Конфигурация мира клиенту недоступна.** В M6 `ConfigLoader` переехал из `Shared` в `Server`:
   netstandard2.1-вариант `Shared` тянул `System.Text.Json`, которого нет в профиле Unity, и `Shared.dll`
   не загружалась в редакторе (см. `docs/state.md`, Discovered Issue #8). Значит, клиент не может
   построить `SimulationConfig` и запустить настоящий `Simulation`.
2. **`LastProcessedClientTick` недостаточен.** Клиент отправляет несколько команд за тик и нумерует их
   `Sequence`; привязка «подтверждён последний клиентский тик» не позволяет отличить «команда применена»
   от «команда отклонена валидатором» — а отклонённые команды тоже нужно подтверждать, иначе клиент
   повторяет их при каждой реконсиляции.

## Решение

### 1. Протокол версии 3 (ADR-004 разрешает смену версии вместе с форматом)

- В `HelloAck` добавлено поле `moveSpeed` (float, little-endian). Полезная нагрузка: 16 байт —
  `entityId u32, tick u32, actorId u32, moveSpeed f32`.
- Новое сообщение `MessageType.ServerAck = 7`, полезная нагрузка 12 байт:
  `entityId u32, acknowledgedSequence u32, tick u32`. Доставка — `ReliableOrdered`, каждый тик,
  **до** снапшота того же тика.
- Запись сущности в снапшоте (ADR-008, 57 байт) не меняется.

### 2. Подтверждение — по `Sequence`, а не по клиентскому тику

Сервер ведёт `ClientSession.AcknowledgedSequence` и сдвигает его только вперёд при получении любой
декодируемой команды — **включая отклонённые** валидатором. Клиент по паре `(tick, sequence)` понимает,
какие команды уже отражены в серверном снапшоте на этом тике, а какие ещё нет.

### 3. Предсказание — правило движения, а не копия симуляции

Клиент строит `ClientPrediction(entityId, moveSpeed)` из HelloAck и повторяет единственное правило
`Simulation.Tick` для `MoveCommand`: `position += direction * moveSpeed * dt`, `dt = 0.05`.
Неподтверждённые команды хранятся очередью; при реконсиляции база — серверная позиция, к ней заново
применяются команды с `Sequence > ack`.

Это сознательное отступление от ADR-006 п.1–2 (копия `Simulation` + кольцевой буфер 128 тиков):
для целей M7 (предсказывается только движение, ADR-006 п.8) копия симуляции не нужна, а её цена —
синхронизация конфигурации мира на клиент. Формула движения — три строки, и её совпадение с сервером
проверяется тестом сходимости (`Pipeline_ConvergesWithDelayAndLoss`), а не «на глаз».

### 4. Реконсиляция — только по согласованной паре «снапшот + ack»

Клиент хранит до 40 последних ack по тикам. Реконсиляция запускается, когда пришёл снапшот с тиком `T`
и в истории есть ack для `T`. Это устраняет ложные срабатывания при задержке: ack приходит быстро,
снапшот — на 2 тика позже, и пара всё равно находится. Порог (`ClientPrediction.Tolerance = 0.01`)
— часть контракта ADR-006; ниже порога предсказание не трогается.

### 5. Локальный игрок — без задержки (dead reckoning), удалённые — буфер 100 мс

Требования к картинке разные: локальному игроку важна отзывчивость управления, удалённым — плавность.

**Локальный игрок (`LocalPredictionSmoother`).** Позиция рисуется сразу по последнему предсказанию,
без задержки буфера. Между тиками (20 Гц) позиция экстраполируется по времени — dead reckoning
`position + velocity * timeSinceSample`, горизонт не больше одного тика, а <b>скорость берётся из
отправленной команды</b> (направление × `moveSpeed` из HelloAck), а не из разности сэмплов: остановка
мгновенная, шум позиций не превращается в ложную скорость. Сэмплы подаются каждый клиентский тик,
поэтому их тайминг не зависит от джиттера сети (снапшоты лишь поправляют предсказание). Коррекция
реконсиляции не телепортирует: расхождение «мы уехали вперёд» уходит в визуальный оффсет и затухает
за ~120 мс; расхождение меньше 0.02 игнорируется как погрешность float; телепорт (респавн, разрыв
> 2 единиц) — мгновенный сброс.

**Удалённые игроки.** Идут через `SnapshotBuffer` с задержкой `LagTicks = 2` (100 мс) и интерполяцией
между соседними снапшотами — как в M6. Им задержка не мешает, зато сетевые рывки и потери
«съедаются» буфером.

Логика сглаживания — чистый код `Client.Network` (`LocalPredictionSmoother`, юнит-тесты), Unity-слой
только передаёт позицию и скорость и рисует результат.

### 6. Лог реконсиляций

`ClientPrediction.Reconciled` → запись в `ClientPipeline.LogEntries` и `Debug.Log` в Unity:
`[reconcile] tick=… error=… predicted=(…) server=(…)`. Это требование Auto-Gate M7.

## Альтернативы

| Вариант | Почему отклонён |
|---|---|
| Копия `Simulation.Core` на клиенте (как в ADR-006) | Нужен `SimulationConfig` на клиенте: либо тащить `System.Text.Json` в Unity (ломает загрузку сборки), либо дублировать конфиг по сети — больше работы и риска, чем выигрыш в точности для движения |
| Подтверждать `LastProcessedClientTick` внутри снапшота | Меняет 57-байтовую запись ADR-008 и не различает применённые/отклонённые команды |
| Подтверждать только применённые команды | Клиент вечно повторяет отклонённую команду → расхождение и «дрожание» |
| Реконсиляция телепортом к серверной позиции | Прямо названный AI-Failure Mode M7: рывки и потеря отзывчивости |
| Предсказывать урон/HP | ADR-006 п.8: серверные значения принимаются как есть |

## Последствия

- Клиент обязан знать `moveSpeed` актора; при смене актора/конфига (M9) HelloAck должен пересчитываться.
- Любая новая предсказываемая механика (способности) потребует либо расширения предсказания, либо
  синхронизации конфигурации — это отдельное решение на M9+.
- `Sequence` становится частью контракта подтверждения: монотонность в рамках сессии обязательна.
- Тесты: юнит «откат + повтор, не телепорт» (`ClientPredictionTests`), сходимость при 100 мс и 20%
  потерь (`Pipeline_ConvergesWithDelayAndLoss`), отсутствие реконсиляций на стабильной сети
  (`Pipeline_StableNetwork_DoesNotReconcile`), ack для отклонённых команд (`ServerAckTests`).
