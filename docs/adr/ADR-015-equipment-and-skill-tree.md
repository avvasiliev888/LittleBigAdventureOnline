# ADR-015. Снаряжение и «Дерево навыков»: бонусы предметов, Слава по архетипам, пороги узлов

**Статус:** принят (Этап 2 плана, вертикальный срез)
**Дата:** 2026-11-11
**Связано:** `docs/PLAN.md` (Этап 2, этап 3, этап 5), ADR-005, ADR-007, ADR-013, ADR-014

## Контекст

PLAN Этап 2 требует: слоты снаряжения, влияние предметов на урон/здоровье/скорость,
`config/skill-tree.json` с линейными ветками для 2–3 архетипов оружия, Славу за убийства и
сбор ресурсов, разблокировку узлов и смену активной способности при смене оружия, плюс
unit-тесты «экипировка даёт Славу, узел открывается по порогу, смена оружия не сбрасывает
прогресс».

Ограничения те же, что у этапа 1: симуляция без Unity (ADR-001), числа только в JSON (ADR-005),
детерминизм (ADR-003/007), снапшот меняется только по ADR (ADR-004/ADR-014).

## Решение

### 1. Предметы дают бонусы, характеристики — производные

`items.json` расширен полями `archetype` (только для оружия в `mainHand`), `damageBonus`,
`maxHpBonus`, `moveSpeedBonus` (доля, 0..1). Сырьё не может иметь ни архетипа, ни бонусов;
не-оружейные слоты не могут иметь `archetype`/`damageBonus`.

Производные характеристики `EntityState` пересчитываются `RecalculateStats(config)`:

```text
MaxHp            = actor.MaxHp + Σ(maxHpBonus снаряжения)   + пассивка ветки
MoveSpeed        = actor.MoveSpeed * (1 + Σ(moveSpeedBonus) + пассивка ветки)
DamageMultiplier = 1 + пассивка ветки
AbilityId        = активный узел ветки оружия, иначе abilityId актора (без оружия)
```

`MaxHp`/`MoveSpeed`/`AbilityId`/`DamageMultiplier` стали `{ get; private set; }`: их нельзя
править извне, только пересчитать из конфига. Сломанная вещь (прочность 0) остаётся надетой,
но бонусов не даёт. Урон способности: `round((ability.Damage + оружие.DamageBonus) * DamageMultiplier)`.

### 2. Слава копится по архетипу, а не «в персонажа»

`FameProgress` — `SortedDictionary<string,int>` на сущности: ключ — архетип оружия. Слава
начисляется:

- убийце-игроку за death жертвы: `victim.Actor.FameOnKill` (новое поле `actors.json`);
- за сбор ресурса: `famePerGather` жилы.

Слава идёт **только** в ветку оружия в руке. Без оружия Слава не начисляется (некуда). Смерть
и смена оружия Славу не сбрасывают — это и есть «прогресс не теряется».

### 3. Дерево линейное, разблокировка выводится из Славы

`config/skill-tree.json`:

```json
{ "archetypes": [ { "key": "warrior", "name": "Воин", "nodes": [
  { "id": 1, "name": "Рассечение", "fameThreshold": 0, "kind": "active", "abilityId": 2 },
  { "id": 2, "name": "Сила удара", "fameThreshold": 10, "kind": "passive", "damageBonus": 0.05 }
] } ] }
```

Правила валидации: первый узел ветки — активный с порогом 0; пороги строго возрастают;
`id` узла уникален во всём дереве; активный узел обязан указывать способность и не даёт
пассивных бонусов; пассивный — наоборот.

Отдельного «множества открытых узлов» нет: узел открыт, если `fameThreshold <= fame`.
Активная способность — **последний открытый активный** узел (при равенстве порогов порядок
задан конфигом). Пассивные бонусы ветки действуют, только пока надето оружие этого архетипа.

### 4. Смена оружия — мгновенная и из инвентаря

`EquipCommand` берёт предмет из инвентаря, надевает его и возвращает вытесненный предмет
в инвентарь. Смена оружия сразу пересчитывает характеристики и активную способность.
Предмет, которого нет в инвентаре, и сырьё отклоняются валидатором (ADR-014).

### 5. Ресурсные жилы на этом этапе статичны

`config/resources.json` описывает жилы: `id`, `key`, `itemId`, `x/z`, `amount`, `gatherSeconds`,
`famePerGather`, `range`. Жила **не истощается и не респавнится**: у неё нет состояния в мире,
поэтому её не нужно добавлять в снапшот и невозможно рассинхронизировать. Ограничение —
персональный кулдаун сбора и серверная проверка радиуса. Истощение/респавн — этап 3 (экономика),
вместе с полями снапшота.

### 6. Конфиги и хеш

`ConfigLoader` грузит шесть файлов (`actors`, `abilities`, `zones`, `items`, `skill-tree`,
`resources`) и считает SHA-256 по всем шести. `--validate-config-only` проверяет и дерево, и жилы.
Валидатор `SimulationConfig` дополнительно требует: архетип оружия существует в дереве,
активные узлы ссылаются на существующие способности, жила ссылается на сырьё и находится
внутри зон мира.

## Альтернативы

| Вариант | Почему отклонён |
|---|---|
| Хранить открытые узлы отдельным множеством | Дублирует данные: Слава и пороги уже дают ответ; рассинхрон множества и Славы — новый класс багов |
| Слава «в персонажа», общая для всех веток | Смена оружия обнуляла бы смысл выбора архетипа; PLAN требует прогресс на ветку |
| Пассивки всех веток всегда активны | «Дерево» превращается в сумму бонусов; выбор оружия перестаёт что-либо значить |
| Сразу добавить жилы в снапшот и истощать | Требует `Protocol v6` и клиентской отрисовки; этап 3 всё равно переделывает экономику |
| Пересчитывать характеристики «на лету» в каждом геттере | Дороже и легче забыть; кэш на `EntityState` + один метод пересчёта — детерминированно и тестируемо |

## Последствия

- Новые unit-тесты: `SkillTreeTests`, `ProgressionTests` (Слава, пороги, смена оружия, смерть,
  сбор), тесты кодека и валидатора, тесты конфигов. Покрытие `Simulation.Simulation` — 100% line.
- Баланс меняется правкой JSON: новый узел/жила/оружие — без строк кода.
- Клиент до этапа 5 не видит Славу и снаряжение; клиентское предсказание кулдауна использует
  способность актора, а не оружия. Это известное ограничение, снимается в `Protocol v6`.
- `ActorConfig.FameOnKill` — данные: тюнинг наград за убийство не требует пересборки.
