# Исправлено 21.11.2026: «нет цели» не появлялось, лук не стрелял по убегающей цели

Дополнение к `docs/combat-turn91-done.md`. Две жалобы, обе — мои недоработки
предыдущего дня, обе подтверждены кодом и числом.

## 1. Пробел без видимой цели наводился на цель с любого расстояния

**Причина.** `ClientPipeline.FindNearestEntityTo` **ранжировал** сущности по
расстоянию до курсора и возвращал ближайшую, **без порога попадания**. Метод
честно не имел отката на `FindNearestEntity` — но и не требовал, чтобы курсор
был **на** теле. Поэтому в мире с любой живой сущностью ответ был всегда не 0,
ветка «цель не найдена» не исполнялась никогда, и сообщение «Нет цели для
атаки» было недостижимо. Наведение «с любого расстояния» — прямое следствие:
побеждала ближайшая к курсору, сколько бы метров их ни разделяло.

**Что сделано.** Добавлен `CursorHitSlack = 0.35f`: кандидат учитывается, только
если курсор попал в тело с допуском **0,35 м** (чуть шире силуэта, чтобы попадание
в ступни или по контуру всё ещё выбирало тело). Всё, что дальше, — не цель.

Проводка HUD (`ConsumeNoTargetReport` → `ShowMessage`) была верной и не менялась:
сообщение не показывалось потому, что сигнал не возникал.

## 2. Лук не стреляет по убегающей цели, персонаж дёргается

**Причина, посчитанная** (`F:\dsh-tmp\chase_loop.py`):

| Величина | Значение |
|---|---|
| клиент стреляет с | **7,40 м** (8,0 − 0,6) |
| сервер принимает до | **8,00 м** |
| запас до отказа | **0,60 м** |
| ожидание остановки тела | **4 тика = 0,20 с** |
| моб 3,2 м/с за это время | **0,64 м** |
| итог | **0,64 > 0,60 → сервер отклоняет выстрел** |

Выстрел **всегда** уходил за пределы серверного радиуса, сервер его отбрасывал,
бой продолжался, персонаж снова бежал — отсюда «бежит, дёргается, не стреляет».

**Что сделано.**
- `TrackTargetDistance` — признак «цель сама движется», по смещению её позиции
  за тик (`TargetMovingThreshold = 0,08 м`, половина тика хода моба 0,16 м).
  Признак **не** по изменению дистанции: пока мы догоняем быстрее (4,0 против
  3,2 м/с), дистанция **падает**, и такой тест назвал бы цель стоящей ровно
  тогда, когда её труднее всего догнать.
- Движущуюся цель бьём **на тике входа в радиус**, не дожидаясь остановки тела.
  Стоящую — как раньше, с ожиданием: замах по-прежнему не начинается поверх бега.
- Пока идёт кулдаун, по движущейся цели персонаж **продолжает идти**
  (`TryApproachStep(..., strictReach: true)`), а не стоит. Иначе он терял
  несколько метров и следующий подход был новым спринтом. `strictReach`
  использует порог без гистерезиса, чтобы держать дистанцию, а не вбегать вплотную.
- `IsWithinReach` и `IsWithinFireThreshold` считают дистанцию через общий
  `TryHorizontalDistance` — два порога не могут разойтись.

## 4. Что нельзя ломать

1. **Курсор обязан быть на теле.** Ранжирование без порога — причина и жалобы
   «наводится с любого расстояния», и недостижимого сообщения HUD.
2. **Труп не цель и не трамплин.** Указывая на труп, игрок не получает никого:
   подмена на «следующего живого» — это выбор за игрока.
3. **Признак «цель движется» — по её позиции, не по дистанции.** Обратное
   ломает ровно тот случай, ради которого признак введён.
4. **Ожидание остановки нельзя применять к движущейся цели.** 0,64 м потери
   против 0,60 м запаса — выстрел не пройдёт проверку сервера.
