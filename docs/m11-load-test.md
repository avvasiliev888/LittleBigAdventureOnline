# M11 — нагрузочный тест 20 ботами

Цель: сервер держит **20 ботов**, средний тик ≤ **25 мс**, p99 ≤ **50 мс**, без крашей. Боты
подключаются по настоящему UDP, двигаются и активируют способность; сервер логирует длительность
тика.

## Сервер: метрики тика

`GameServer.Tick` измеряет своё время через `Stopwatch` и складывает выборки в
`ServerMetrics` (ring-buffer на 12 000 тиков ≈ 10 минут при 20 Гц). `ServerMetrics.Snapshot()` даёт
`n / avg / p50 / p99 / max`; строка лога:

```text
tick metrics: n=1301 avg=0.080ms p50=0.057ms p99=0.348ms max=5.494ms
```

Период лога задаётся `--metrics-every <тиков>` (по умолчанию 200, `0` — выкл.), а
`--seconds <сек>` останавливает сервер и печатает `tick final metrics` — это нужно для
автоматического теста. Обычный запуск без `--seconds` работает до Ctrl+C.

```powershell
dotnet run --project src/Server -c Release -- --udp 9050 --metrics-every 200
```

## Боты: `tools/bot-client`

Headless-клиент на том же `LiteNetLibTransport`/`MessageFraming`/`CommandCodec`, что и Unity-клиент:

- Hello и повтор до `HelloAck`;
- движение каждые 100 мс (у каждого бота своя фаза синуса);
- способность каждые 2.2 с по тренировочному манекену (`--target-actor 2`, actor из
  `config/actors.json`), чтобы боты не убивали друг друга и не простаивали мёртвыми;
- раз в 5 с запрашивает полный снапшот, чтобы цель не устаревала;
- если манекен мёртв/не найден, отправляется legal miss (target 0), а не self-target;
- считает snapshots/deltas/acks/commands и завершает процесс с кодом 1, если кто-то не подключился
  или не получил ни одного снапшота.

```powershell
dotnet run --project tools/bot-client -c Release -- \
  --host 127.0.0.1 --port 9050 --bots 20 --seconds 60
```

## Автоматический прогон

```powershell
pwsh -File tools/load-test.ps1 -Bots 20 -Seconds 60
```

Скрипт собирает сервер и ботов, поднимает UDP-сервер на 5 секунд дольше прогона, запускает ботов,
ждёт финальные метрики, проверяет пороги и пишет артефакты:

- `artifacts/m11-load/server.log`
- `artifacts/m11-load/bots.log`
- `artifacts/m11-load/summary.json`

Порог в скрипте: `avg <= 25 ms`, `p99 <= 50 ms`, минимум `15 × seconds` выборок, оба процесса
завершились с кодом 0. `artifacts/` в `.gitignore`.

## Результат 20 ботов / 60 секунд

```text
[bots] done: connected=20/20 hello=20/20 snapshotBots=20/20 snapshots=260 deltas=23950 acks=23970
             moves=11020 abilities=560 disconnects=0
tick final metrics: n=1301 avg=0.080ms p50=0.057ms p99=0.348ms max=5.494ms
PASS
```

- 20/20 подключились, 20/20 получили снапшоты, 0 разрывов, 11 020 move-команд и 560 активаций способности.
- Средний тик **0.080 мс**, p99 **0.348 мс**, максимум **5.494 мс** — с большим запасом к 25/50 мс.
- Метрики включают обработку 20 сессий, валидацию, симуляцию и отправку 20 снапшотов/ack на тик.

## Ограничения

- Тест идёт на loopback одного хоста; сетевые потери/задержка проверяются отдельно
  `--delay/--loss` и не входят в M11-бюджет.
- Боты не рендерят и не предсказывают; это нагрузка на сервер и транспорт, а не проверка Unity.
- Метрика измеряет обработку тика, а не полный wall-clock цикла; цикл дополнительно проверяется
  тестом стабильности `ServerLoopTests`.
- 60-секундный прогон не входит в обычный CI (чтобы не замедлять каждый push); Auto-Gate
  подтверждается `ServerMetricsTests` + `tools/load-test.ps1`, результат приложен к PR.
