# ADR-020: Protocol v8 — поля прогрессии, трупы и клиентский UI Stage 5

## Статус

Принято (Stage 5).

## Контекст

К Stage 5 сервер уже знал о зонах, Славе, серебре, экипировке, флаге враждебности
(ADR-013…ADR-019), но клиент получал только базовые поля сущности и не мог показать
прогрессию. Мобы и трупы Stage 4 были серверными объектами и не попадали в снапшот,
поэтому Unity-клиент не рисовал ни мобов, ни добычу, а HUD не знал зону и Славу.
Кроме того, клиентский кулдаун инициализировался способностью актора и не обновлялся
после смены оружия, хотя сервер выбирает способность по ветке оружия и Славе
(`EntityState.RecalculateStats`).

## Решение

### 1. Снапшот v8

`EntitySnapshot` расширен полями:

| Поле | Тип | Смысл |
|---|---|---|
| `ZoneId` | `uint` | зона, в которой стоит сущность (0 — мир без зон/точка вне зон) |
| `AbilityId` | `uint` | активная способность с учётом оружия и Славы |
| `MoveSpeed` | `float` | скорость с бонусами экипировки |
| `Silver` | `int` | серебро сущности |
| `HostileUntilTick` | `uint` | тик окончания флага враждебности (0 — флага нет) |
| `WeaponItemId`, `ChestItemId`, `LegsItemId`, `FeetItemId` | `uint` | предметы в слотах (0 — пусто) |
| `FameTotal` | `int` | суммарная Слава по всем веткам |
| `BranchFame` | `int` | Слава ветки оружия в руке (0 без оружия) |

`BranchFame` — не «Слава текущей ветки вообще», а именно ветки надетого оружия. Клиент
выводит её из `WeaponItemId` → `ItemDefinition.Archetype` и показывает в дереве навыков;
это позволяет не передавать переменный список веток и сохранить фиксированную запись
сущности (101 байт).

`SimulationSnapshot` получил `Corpses` — список `CorpseSnapshot` (`Id`, `Position`,
`LootRange`, `Silver`, `Loot`, `ExpireAtTick`). Трупы передаются в каждом полном снапшоте
и в каждой дельте целиком: их мало, они статичны и живут секунды, поэтому маска полей для
них не нужна.

### 2. Формат и дельта

Запись сущности осталась фиксированной: 101 байт. Дельта использует `uint`-маску
(`AllFieldMask = 0x1FFFFF`, 21 бит: 10 старых полей + 11 новых). Заголовок дельты — 14
байт (базовый тик, тик, число удалённых, число записей, число трупов). Трупы в дельте
идут после записей сущностей.

Полный формат:

```text
u32 tick
u16 entityCount
entity[entityCount]      // 101 байт каждая
u16 corpseCount
corpse[corpseCount]      // 30 байт + 8 байт на стопку лута
```

### 3. Синхронизация предсказания

`ClientPipeline` при каждом применённом снапшоте берёт запись своего `EntityId` и
обновляет `ClientPrediction`:

* `MoveSpeed` — чтобы локальный шаг совпадал с серверным после смены обуви;
* `AbilityId` → `ClientContent.GetAbility` — чтобы кулдаун и радиус соответствовали
  оружию/Славе, а не стартовой способности.

Кулдаун при смене способности не сбрасывается: сервер присылает абсолютный
`CooldownUntilTick`, клиент реконсилирует остаток по нему.

### 4. Unity-визуал и UI

* Мобы рисуются капсулами: цвет по зоне моба (`blue` — синий, `yellow` — жёлтый,
  `red` — красный), мёртвая сущность скрывается, труп рисуется серой капсулой.
* Игрок получает `MaterialPropertyBlock`-тинт по ветке оружия (warrior/archer/mage),
  броня осветляет оттенок; пустые слоты возвращают исходные материалы.
* Освещение, туман и цвет солнца меняются при входе в зону.
* HUD (IMGUI): HP, ресурс, Слава, серебро, зона, флаг враждебности, кулдаун.
* `C` — крафт (список рецептов и кнопки), `K` — дерево навыков текущей ветки,
  `E` — лут ближайшего трупа в радиусе, панель торговца появляется рядом с NPC.
* Команды UI (`Craft`, `Buy`, `Sell`, `Loot`, `Equip`) отправляются через
  `ClientPipeline.Send*` с собственным монотонным sequence.

## Последствия

* Protocol.Version = 8; старый клиент/сервер несовместимы — это ожидаемо, версия
  проверяется во фрейминге.
* Запись сущности выросла с 57 до 101 байта; дельта остаётся меньше полного снапшота,
  потому что маска передаёт только изменения.
* Инвентарь в снапшот не входит: UI крафта показывает рецепты и материалы, но не
  количество в сумке. Сервер по-прежнему авторитетен и отклоняет нехватку ресурсов;
  это осознанно оставлено за рамками Stage 5.
* Трупы в дельте передаются полностью; при большом числе трупов это допустимо, потому
  что туша живёт ограниченное время и обычно их единицы.
