# ADR-021. Серверные коллизии без физики Unity

**Статус:** принят
**Дата:** 2026-11-11
**Связано:** ADR-001, ADR-005, ADR-006, ADR-011, `docs/PLAN.md` §6.9

## Контекст

Мир процедурный, а движение авторитетно на сервере. Если использовать `Collider`/`Rigidbody` Unity на клиенте, клиент и сервер начнут расходиться: сервер не знает о физических препятствиях, а клиентское предсказание будет «застревать» там, где сервер разрешает движение. Физика Unity также недоступна в `Simulation.Core` (ADR-001).

## Решение

1. **Статические препятствия — данные, не физика.** Генератор сцены экспортирует деревья, камни, столбы и страж-камни прохода в `config/world-colliders.json`: `id`, `kind`, `x`, `z`, `radius`. Файл входит в общий хеш конфигов (ADR-011), поэтому сервер и клиент не могут играть с разными препятствиями.
2. **Один алгоритм движения.** `MovementCollision.Resolve` в `Simulation.Core`:
   - ограничивает шаг зонами и проходами (`ZoneMap.ResolveMovement`);
   - находит первое пересечение шага с расширенным кругом препятствия;
   - ставит актора на касательную и отбрасывает нормальную составляющую шага — это скольжение;
   - в конце повторно проверяет границы зон и выталкивает из остаточного перекрытия.
3. **Динамические препятствия — круги акторов.** Игроки и мобы имеют `collisionRadius` в JSON; движущийся актор не проходит сквозь другого. `ResolveOverlaps` мягко расталкивает пересечения после спавна/респавна и восстановления снапшота.
4. **Сервер и предсказание — один код.** `Simulation.ApplyMove`/`MoveMobTowards` и `ClientPrediction.Step` вызывают `MovementCollision.Resolve`. Клиент получает круги удалённых акторов из последнего снапшота; расхождение при движении удалённого актора гасится обычной реконсиляцией (ADR-006).
5. **Unity не получает физических коллайдеров для передвижения.** Если камере или курсору понадобится невидимый коллайдер, он будет только вспомогательным и не должен влиять на позицию персонажа.

## Альтернативы

| Вариант | Почему отклонён |
|---|---|
| `CharacterController`/`Rigidbody` на клиенте | Расходится с сервером, ломает предсказание и авторитет |
| Физика только на сервере через Unity | `Simulation.Core` обязан быть без Unity; сервер headless |
| Растровое поле проходимости | Сложнее экспорт, грубее форма деревьев/камней; круги достаточны для среза |
| Не делать динамические коллизии | Игроки и мобы проходят друг сквозь друга — критический дефект |

## Последствия

- Изменение сцены требует повторного экспорта `world-colliders.json` (`Albion/World/Export World Colliders`); иначе визуальные и серверные препятствия разойдутся.
- Число статических препятствий (~584) требует дешёвой проверки на тик; текущая линейная проверка укладывается в бюджет 20 Гц, при росте мира — spatial hash.
- Проходимость не является физикой: никаких сил, трения и прыжков; только движение по плоскости X/Z.
