# Лук и стойка стрельбы — состояние работ

Рабочий журнал по луку как отдельному оружию. Нужен, чтобы калибровка не терялась
между сессиями: все числа ниже подобраны вручную в окне превью и **не являются
догадкой**. Менять их можно только вместе с оператором.

## Как запустить

`Albion → Animation → Preview Window` (Ctrl+Shift+P) или
`Albion → Animation → Preview Warrior Attack`.
Кнопка **«Лук»** в разделе «Оружие в руках» восстанавливает всю калибровку целиком.

## Эталонная калибровка лука

Лук сидит в **левой** руке. Пресет `ApplyBowPreset()` в
`unity-client/Assets/Editor/AnimationPreviewWindow.cs`.

| Параметр | Значение |
|---|---|
| Кость | `Left Hand` |
| Смещение | X **0.09** Y **0.12** Z **-0.15** |
| Поворот | X **90** Y **90** Z **-95** |
| Масштаб | **1** |
| Разворот кисти | **90** |
| Доворот оружия | X 0 Y 0 Z 0 |
| Поворот модели | **5.546** |
| Поворот головы | **-82.16** |

**Статус: калибровка подтверждена оператором.** Лук встаёт вертикально сразу при
`Z -95`, без «прогрева» — достаточно нажать «Лук» и дождаться появления. Ранее
казалось, что `-95` не работает, а `-96` работает: причиной было накопление ошибки
(см. ловушку №3), а не сами числа. Значение `-95` верное, менять не нужно.

Те же числа продублированы в `Assets/Resources/Characters/WarriorVisual.asset`
(запись `Kind: 3` — лук) и в полях `BowHandRoll` / `BowHeadTurn` того же asset.

### Замеры, подтверждающие позу

В окне превью, раздел отчёта:

- `ГОЛОВА vs ЛУК` ≈ **−13°…−15°** — недоворот головы, заложен намеренно
  (`GazeSlack`), чтобы голова не выглядела жёстко приклеенной к луку.
- `Корпус` ≈ **98°** — арчер стоит боком. Это **норма**, не дефект.
- `Стрела к модели` ≈ **−5°**.

## Префаб игрока (важно: было сломано)

В игре показывался **чиби-рыцарь из примитивов**, а не воин dReal. Причина:
`Warrior.prefab` от вендора содержал **только два пустых объекта** — `RightHandSocket`
и `LeftHandSocket`, без меша, скелета и Animator. Логика в
`CharacterVisualSettings.Create` выбирает путь по наличию `CharacterVisuals`:
нет компонента → уходит в `CreateLegacyWarrior`, который строит заглушку кодом.
То есть dReal-воин **до игры не доходил вообще** — он жил только в окне превью.

Исправлено скриптом `Assets/Editor/WarriorPrefabBuilder.cs`,
меню **`Albion → Characters → Rebuild Warrior Prefab From FBX`**.
Он пересобирает префаб из `Warrior.fbx`, сохраняет вендорские смещения сокетов,
ставит Animator с `WarriorLocomotion.controller`, добавляет `CharacterVisuals`,
перевешивает `WarriorVisual.asset` и проверяет наличие меша, Humanoid-аватара
и контроллера.

Прогнано успешно. Итог: `Prefab: fileID 1052260892624195920, guid 2412842c…`,
в префабе объекты `Warrior`, `LeftHandSocket`, `RightHandSocket`.

**Мобы по-прежнему на заглушках**: `MobVisuals.asset` ссылается на
`Art/Characters/Generated/Skeleton_*`, которые собраны тем же примитивным путём.
Отдельная задача, не трогали.

## Ловушки, на которые уже наступали
Записано, чтобы не повторять:

1. **Кость вращать нельзя, измеряя по её осям.** У Mixamo и dReal локальные оси
   костей скручены относительно тела. Мерить только **позициями костей**
   (`Cross(rightShoulder - leftShoulder, Vector3.up)` для корпуса).
2. **Коррекции только после `SampleAnimation`.** Клип перезаписывает все кости,
   которых касается, при каждом сэмпле.
3. **Коррекция обязана считаться от исходного состояния.** Если читать поворот
   оружия обратно как «эталон», ошибка копится каждый кадр и лук уползает.
   Именно это давало ложное ощущение «−95 не работает, а −96 работает»: работала
   не цифра, а пересборка оружия. Исправлено: при креплении запоминается авторский
   локальный трансформ (`CaptureAuthored`), и перед каждой коррекцией оружие
   возвращается к нему. Подтверждено оператором — «прогрев» больше не нужен.
4. **90° между корпусом и рукой лучника — это норма.** Порог «руки отклонены
   больше 35° → всё сломано» был ложной тревогой, критерий удалён.
5. **Симметричное вращение не видно.** Вращение лука вокруг его собственной длинной
   оси визуально ничего не меняет.
6. **Лук и кисть — разные оси.** «Разворот кисти» крутит вокруг предплечья,
   «Доворот оружия» — вокруг рукояти. Одним слайдером не совмещаются.
