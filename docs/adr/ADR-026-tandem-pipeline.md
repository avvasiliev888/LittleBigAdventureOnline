# ADR-026: Конвейер «Тандем» — платное планирование, локальное исполнение, гейты

- **Статус**: принято (установка)
- **Дата**: 2026-11-22
- **Контекст**: правки в этом репозитории делают агенты под управлением платной модели.
  Каждый шаг стоит денег и контекста (замер: 1,58 млрд токенов на 10 сессий, 92,5% —
  перечитывание). При этом большая часть работы — механическая: правка по готовому плану.
  Хочется, чтобы дорогая модель планировала и проверяла, а писать код умела локальная
  модель бесплатно, но при этом качество падало только в тех случаях, когда это
  доказано ревью и гейтами, а не «когда агент устал».

## Решение

### 1. Разделение ролей и моделей

| Роль | Модель | Провайдер |
|---|---|---|
| Архитектор (план, ADR, отчёт) | `deepseek-v4-flash` | `openai` (LiteLLM) |
| Исполнитель (код) | `ois-gemma-4-26B` | `openai` (LiteLLM) |
| Ревьюер (diff + логи) | `deepseek-v4-flash` | `openai` (LiteLLM) |
| Отладчик (после 4 неудач) | `deepseek-v4-flash` | `openai` (LiteLLM) |
| Гейты | `tools/tandem/gates.ps1` | локально, $0 |

Планировщик и ревьюер — одна модель: обе задачи требуют понимания архитектуры
и обе дешёвы относительно правок. Исполнитель — локальная модель: он получает
готовый, нарезанный до ≤2 файлов и ≤150 строк план, а не свободу творчества.

### 2. Гейты — единственный судья «работает ли»

`tools/tandem/gates.ps1` последовательно прогоняет build → test → архитектурные
скрипты → Unity compile и возвращает JSON. Стоп на первом провале, в JSON только
`ok`, `failed_step` и хвост лога (40 строк); полные логи — `docs/reports/logs/`.
Причина: вердикт «на глаз» уже дважды пропускал ошибки компиляции Unity, которые
`dotnet build Prototype.sln` не видит (в решении нет `unity-client`).

### 3. Последовательный режим и человек в конце

Одна задача за раз, ветка `agent/T-<slug>` от `main`, мерж — только по письменному
«принято». Параллельные ветки запрещены: конфликты обходятся дороже, чем экономятся.
ПК-билд собирается только после `PASS` ревью.

### 4. Флаг `.agent/away`

«Я уезжаю» → создаётся `.agent/away`, агент шлёт Telegram-пинги и продолжает
работать по плану. «Я вернулся» → файл удаляется, агент присылает сводку.
Флаг локальный (в `.gitignore`): состояние машины, а не репозитория.

### 5. Бюджет как жёсткий, а не мягкий предохранитель

`$8/мес` — мягкий стоп (остановиться и спросить), `60` платных вызовов — жёсткий
лимит. Перед каждым платным вызовом читается `.agent/spend.jsonl`. Стоимость
и пределы лежат в `.agent/config.json`, чтобы их правка не требовала правки кода.

### 6. Тело оркестратора — `tools/tandem/orchestrator.workflow.js`

Файл не самостоятельный скрипт: тело DSH-workflow не имеет файловой системы,
сети и shell. Поэтому парсинг плана, `git` и запуск `gates.ps1` выполняют агенты
(у них есть инструменты), а скрипт раскладывает фазы и принимает решения по их
структурированным ответам.

## Последствия

- Дешёвые итерации: код пишет локальная модель, платная — только план, ревью и разбор.
- Стоимость ошибки ограничена: 3 попытки исполнителя, затем отладчик, затем стоп.
- Бюджет нельзя превысить молча — только остановкой с отчётом.
- Появляется требование к gemma: tool calling. Если он «плывёт», fallback —
  gemma генерирует патч, применяет скрипт (проверяется пилотом, `docs/TANDEM_SETUP_PLAN.md` § 9.1).
